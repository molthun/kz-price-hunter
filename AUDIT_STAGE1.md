## Что изменилось

| Пункт аудита | Результат |
|---|---|
| C01 — XSS | Названия, категории, магазины, AI-подсказки, tracked queries и строки логов экранируются для HTML/атрибутов. Данные действий передаются как экранированный JSON и обрабатываются через addEventListener, без вставки данных в исполняемый JavaScript. |

| H04 — секреты в файлах | Добавлены исключения env, private keys и backups в Git/Docker, включая вложенные пути Docker. `.env.example` разрешён; реальные credentials не переносились и не менялись. |
| M02 — ошибки и логи | Убраны тела ответов Telegram/AI и сырые транспортные ошибки из известных путей. Типовые tokens, API keys, Authorization и секретные query-параметры редактируются до терминала/буфера/экспорта. Ошибки API санитизируются, ошибки сканирования не раскрывают текст исключения. |

Редактор логов — дополнительный барьер, а не универсальный детектор любых секретов или персональных данных. Незавершённые строки удерживаются до перевода строки, в том числе при flush: это предотвращает утечку токена через раздельные write-вызовы. Вывод без завершающего перевода строки задерживается.

## Сохранённые границы

Хеши database.py, settings.json, config.py, model_matching.py и всех scrapers совпадают с началом этапа. В auth.py изменены только диагностические сообщения getMe; проверка подписи, cookies, сессии, права dev login не переписаны. В AI/Telegram изменено логирование ошибок, не выбор моделей/провайдеров и не логика отправки.

Миграции рабочей БД, canonical_key и её данные не менялись нашими действиями. Уже работающий процесс может продолжать менять prices.db; неизменность всей рабочей БД не заявляется. Временная тестовая БД создавалась и мигрировала только в изолированном DATA_DIR.

Сервер не перезапускался: его запуск вызывает init_db с миграциями из отдельного этапа аудита. Поэтому исправления backend подтверждены тестами локального кода, но не действующим сервером. Перед применением к работающему экземпляру нужны согласованные проверка миграций и резервная копия БД.
