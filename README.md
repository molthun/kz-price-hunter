# 🎯 KZ Price Hunter

Мониторинг цен в крупнейших сетях электроники Казахстана: поиск ценовых ошибок («пропущенный ноль»), глубоких скидок и межмагазинного арбитража. Результаты выводятся в веб-панели и отправляются в Telegram.

## Текущие изменения (v3.3.0, локально)

Обход различает полный, ограниченный и неудачный результат; при сбоях выполняются отложенные повторы. Неактуальные предложения исключаются из поиска, каталога и ленты. Исчезновение подтверждается только полным обходом источника, а срок свежести цены — максимум из 24 часов и двух интервалов сканирования.

Сравнение моделей консервативное, с учетом модификации, памяти и города. Telegram использует постоянную очередь с повторными попытками. В администрировании добавлена таблица состояния магазинов и запуск отдельного источника.

Основной регион сбора — Астана. Flip.kz подключен для электроники; пока город наличия не подтвержден, его товары видны только в «Все города» и не участвуют в региональном арбитраже.

## Возможности

- **🚨 Аномалии цен** — «пропущенный ноль»: цена упала в 8–12 раз относительно истории цен в базе или зачеркнутой цены на сайте.
- **🔥 Супер-скидки** — падение цены от заданного процента и суммы выгоды.
- **⚖️ Межмагазинный арбитраж** — товар заметно дешевле самой низкой цены того же товара в других сетях.
- **🔍 Поиск лучшей цены** — поиск по всем магазинам через SQLite FTS5 (режимы «все слова» / «любое слово», минус-слова, фильтры по цене и магазину); по желанию — прямой опрос Kaspi, Белого Ветра и 4mobile.
- **📦 База товаров** — каталог 20 000+ товаров с поиском и фильтром по магазину.
- **🤖 Автообновление базы** — фоновое сканирование, когда база старше заданного интервала (5 минут – 30 дней, по умолчанию 3 часа).
- **📨 Telegram** — уведомления с фото товара и выбором уровня: все аномалии, только «пропущенный ноль» или только крупные скидки.
- **📜 Логи (Live)** — системные логи в реальном времени прямо в панели, с фильтрами и выгрузкой.
- **📍 Регион** — выбор города Казахстана, автоопределение по геолокации (только по HTTPS или на localhost) или по IP.
- **👤 Аккаунты** — вход через Telegram; у каждого пользователя свои пороги, минус-слова, магазины в ленте и уведомления.

## Пользователи и доступ

| Кто | Что доступно |
|---|---|
| **Гость** (без входа) | Аномалии, скидки, поиск по базе и каталог — с настройками по умолчанию |
| **Пользователь** (вход через Telegram) | Личные пороги аномалий, минус-слова, магазины в ленте, Telegram-уведомления, прямой опрос магазинов (Live, не чаще 10 раз за 10 минут) |
| **Администратор** (`ADMIN_TELEGRAM_IDS`) | Плюс общие настройки: интервал сканирования, сканируемые магазины, пороги записи кандидатов, ручное сканирование, логи, блокировка пользователей |

Сканер сохраняет «кандидатов» по мягким общим порогам, а лента, счетчики и Telegram-уведомления каждого пользователя фильтруются по его личным настройкам.

**Настройка входа через Telegram:**
1. Создайте бота у [@BotFather](https://t.me/BotFather) и укажите домен сайта: `/setdomain` → домен вашего сайта.
2. Передайте контейнеру `TELEGRAM_BOT_TOKEN` и свой Telegram ID в `ADMIN_TELEGRAM_IDS` (узнать ID можно у [@userinfobot](https://t.me/userinfobot)).
3. Пользователь входит кнопкой «Log in with Telegram» и разрешает боту писать ему — уведомления приходят в личный чат с ботом.

## Деплой (прод)

```
push в main ──► GitHub Actions: тесты ──► сборка образа ghcr.io/molthun/kz-price-hunter:latest
                                                   │
          Synology (Docker) ◄── Watchtower проверяет образ каждые 5 минут
                 │
          Reverse proxy DSM ──► https://<ваш-домен>
```

- **Любой пуш в `main` уходит на прод примерно через 5 минут.** В CI тесты запускаются до сборки: если они падают, образ не собирается.
- `latest` публикуется **только из `main`**. Теги `vX.Y.Z` собирают образы с номером версии (`:2.9.0`) — на них можно откатить прод.
- Контейнер описан в [`docker-compose.yml`](docker-compose.yml): порт `35539`, данные (база и `settings.json`) в томе `./data` → `/app/data`.
- GitHub не запускает сборки, если за один пуш отправлено больше трех тегов — пушьте теги по одному.

## Локальный запуск

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/playwright install chromium   # нужен скраперам DNS, Технодом и Kaspi
./venv/bin/python3 gui.py
```

Панель откроется на `http://localhost:8080`, в локальной сети — `http://<ip-компьютера>:8080`.

Виджет входа Telegram работает только на домене бота, поэтому при локальном запуске (не в Docker) в шапке появляется кнопка **«Вход разработчика»** — она входит с правами администратора. Ничего настраивать не нужно: достаточно `./venv/bin/python3 gui.py`. Кнопка работает только с localhost и локальной сети; выключить ее можно переменной `ALLOW_DEV_LOGIN=0`.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт веб-панели |
| `DATA_DIR` | папка проекта | Где лежат `prices.db` и `settings.json` |
| `APP_URL` | — | Адрес панели для кнопки «Дашборд цен» в Telegram-уведомлениях; без него кнопка не показывается |
| `TELEGRAM_BOT_TOKEN` | — | Токен бота для входа на сайте и уведомлений (в интерфейсе не показывается) |
| `ADMIN_TELEGRAM_IDS` | — | Telegram ID администраторов через запятую |
| `ALLOW_DEV_LOGIN` | авто | Кнопка «Вход разработчика» с правами администратора для локальной разработки. Без переменной включается сама при запуске не в Docker; `0` — выключить, `1` — включить. Работает только с localhost / локальной сети без reverse proxy. В Docker-образе выключена (`ALLOW_DEV_LOGIN=0`) |

### Консольный режим

```bash
./venv/bin/python3 main.py --once   # один цикл сканирования
./venv/bin/python3 main.py          # сканирование по кругу
```

> CLI использует общий сканер, настройки интервала и очередь Telegram. После `--once` отложенные повторы сохраняются в базе и продолжатся при следующем запуске CLI или веб-панели.

### Тесты

```bash
./venv/bin/python3 test_monitor.py
```

Тесты работают на временной базе и не трогают `prices.db` и `settings.json`.

## Настройки

Настройки меняются во вкладке **«Настройки»**. Личные хранятся в базе у каждого пользователя, общие — в `settings.json` внутри `DATA_DIR` (файл не хранится в git). Сервер проверяет значения при сохранении: неизвестные поля отбрасываются, отрицательные числа и неверные типы отклоняются.

| Группа | Кто меняет | Что настраивается |
|---|---|---|
| Детекция аномалий | Пользователь | Типы аномалий, мин./макс. цена товара, мин. скидка (%) и выгода (₸), порог арбитража (% и ₸) |
| Стоп-слова | Пользователь | Минус-слова для аксессуаров, исключение уцененных и б/у товаров |
| Поиск по умолчанию | Пользователь | Сортировка, исключение аксессуаров (прямой опрос магазинов всегда выключен по умолчанию) |
| Telegram-уведомления | Пользователь | Включение, уровень алертов, тестовое сообщение |
| Магазины в ленте | Пользователь | Какие магазины показывать в ленте и уведомлениях |
| Пороги записи кандидатов | Администратор | Мягкие пороги, по которым сканер сохраняет аномалии |
| Сканирование магазинов | Администратор | Интервал автообновления базы, сканируемые магазины |
| Пользователи | Администратор | Список пользователей, блокировка |

## Структура проекта

```
gui.py              — точка входа: запуск веб-панели (aiohttp)
web/server.py       — API и фоновое сканирование
auth.py             — вход через Telegram, сессии, права доступа, лимиты запросов
web/templates/      — веб-интерфейс (одна страница, Tailwind)
scrapers/           — скраперы магазинов
detector.py         — детекция аномалий, скидок и арбитража
search_engine.py    — поиск лучшей цены (FTS5 + прямой опрос)
database.py         — SQLite (WAL + FTS5): товары, история цен, алерты
config.py           — настройки, категории, города
notifier.py         — Telegram-уведомления
log_manager.py      — перехват логов для вкладки «Логи»
main.py             — консольный режим
test_monitor.py     — тесты
version.py          — версия приложения
```
