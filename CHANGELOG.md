## [3.3.0] — 2026-09-18
- Результаты обхода: полный, ограниченный, частичный, неудачный. Ошибки HTTP/структуры больше не выдаются за успешный пустой каталог; повтор через 5 минут с увеличением паузы до часа. Лимит страниц и неподтвержденный конец HTML-выдачи не считаются полным обходом.
- Исчезновение предложений учитывается по источнику/категории только после полного непустого обхода. Неполные обходы сохраняют найденные товары, но не скрывают отсутствующие. Существующие предложения без привязки к источнику выводятся из выдачи по сроку свежести.
- Поиск, каталог, лента и сравнение исключают неактивные и устаревшие цены: срок — максимум из 24 часов и двух интервалов сканирования. Лента также скрывает алерт, если текущая цена изменилась.
- Сопоставление моделей стало консервативным: одинаковые значимые токены, модификации и память; нормализация GB/ГБ и TB/ТБ; сравнение только одного подтвержденного города. Возможны пропуски одинаковых товаров с разными обозначениями; неоднозначные совпадения не используются.
- Межмагазинная проверка больше не ограничена первыми 100 товарами категории; запросы вынесены из основного цикла веб-сервера.
- Алерт и персональные задания Telegram сохраняются одной транзакцией. Очередь переживает перезапуск, повторяет неудачные отправки (до 8 попыток, до 24 часов), отменяет задания при блокировке, отключении уведомлений или изменении цены. Дедупликация алертов ограничена 24 часами. При сбое после приема сообщения Telegram, но до записи успеха возможен повтор сообщения.
- Панель администратора показывает результаты по магазинам, время попытки, количество товаров, ошибки, время повтора и счетчики очереди. Есть запуск отдельного магазина; API проверяет список магазинов.
- CLI использует общий интервал и очередь; отдельная YML-кнопка теперь запускает общий защищенный обход с детекцией.
- Добавлен Flip.kz: HTML-каталог электроники, пагинация, цена отдельно от зачеркнутой и проверка наличия. Город не подтвержден: предложения доступны в «Все города», исключены из регионального арбитража. Источник: https://www.flip.kz/catalog?subsection=5319. Проверены первые две страницы — 120 уникальных товаров; полный каталог не замерялся.
- Сохранены существовавшие до этой работы правки пакетной записи и кэширования ленты; соединения SQLite теперь закрываются после транзакций.
- Проверки: 27 тестов на временной базе; двукратная миграция копии рабочей базы — 20 928 товаров сохранены, integrity_check=ok; таблица магазинов проверена в браузере на изолированном экземпляре. Реальная отправка Telegram и полный производственный обход не выполнялись.

## [3.0.0] — 2026-09-17

### ⚠️ Несовместимые изменения
- Вход, роли и личные настройки: общий `settings.json` больше не хранит пороги, минус-слова и Telegram-чат. Эти настройки теперь у каждого пользователя в базе.
- Уведомления в Telegram приходят только пользователям, которые вошли на сайте и включили уведомления в «Настройках». Старая рассылка в один `telegram_chat_id` отключена.
- Токен бота задается переменной окружения `TELEGRAM_BOT_TOKEN` (старое поле `telegram_bot_token` в `settings.json` пока читается для совместимости). Администраторы — `ADMIN_TELEGRAM_IDS`.
- API: удалены `GET/POST /api/config` и `POST /api/test-telegram`; сканирование, YML-выгрузка и логи доступны только администратору.

### Добавлено
- 👤 **Вход через Telegram** (Telegram Login Widget) с проверкой подписи, сессиями в HttpOnly-cookie на 30 дней и выходом из аккаунта. Регистрация открыта для всех.
- ⚙️ **Личные настройки у каждого пользователя**: пороги аномалий, минус-слова, исключение б/у, настройки поиска, магазины в ленте, Telegram-уведомления (включение, уровень, тестовое сообщение в личный чат).
- 🛡 **Раздел «Администрирование»**: пороги записи кандидатов, интервал сканирования и сканируемые магазины, статус бота, список пользователей с блокировкой.
- 🎯 **Кандидаты и персональная лента**: сканер сохраняет аномалии по мягким общим порогам; лента, счетчики и уведомления фильтруются по личным порогам. При первом входе администратор получает пороги из прежнего `settings.json`.
- 🚦 **Защита публичного сервиса**: проверка Origin для изменяющих запросов (CSRF), прямой опрос магазинов только после входа и не чаще 10 раз за 10 минут, ограничения частоты поиска и попыток входа, экранирование названий товаров в уведомлениях.
- 🧑‍💻 **Вход разработчика** для локальной разработки (`ALLOW_DEV_LOGIN=1`, только без reverse proxy и из локальной сети).

### Исправлено
- Шапка на телефоне больше не растягивает страницу по ширине: элементы переносятся, описание скрывается, шапка закреплена только на широких экранах.
