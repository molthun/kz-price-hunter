# SC-01: дубли Moon и Вкусмарт

02.11.2026, Codex по прямому поручению владельца. База 1d18fc6, версия 6.18.5.
Один исполнитель; чужие untracked сохранены. Production и push main исключены.

## Исправление

Проверка seen_ids перенесена после вычисления окончательного ID из data-id или ссылки.
Moon добавляет ID в seen_ids только после успешного разбора карточки; Вкусмарт сохраняет
свою существующую проверку validate_product_item перед добавлением.

Вложенная карточка без data-id больше не создаёт вторую строку с тем же fallback ID.
Невалидная внешняя карточка не блокирует корректную внутреннюю. Разные ID, даже при одинаковых
названии/URL, остаются отдельными предложениями. Первая валидная цена одного ID сохраняется.
Названия, формирование ID, цены и параметры запросов не изменены.

Общий контроль качества, baseline, пороги дублей/объёма, лимиты страниц и полная/частичная
сверка каталога не менялись. Полный обход не запускается; результаты ручных проб в каталог не пишутся.
Исторические ошибки не стираются ради зелёного статуса: новая оценка появится после штатного обхода.

## Проверки

Шесть регрессий для обоих адаптеров: nested fallback, native/fallback collision и первая цена,
невалидная внешняя/валидная внутренняя, разные native IDs с одинаковым URL, неизменные fallback ID
и название, ограничение одной страницы без ложного complete.
Профильный набор scraper contracts/completeness/reliability: 132 PASS + 12 subtests.
Временные данные, синтетический HTML, без сети и рабочей БД. Release/compile/secrets/diff-check отдельно.

На стенде планируется сравнение старого и нового парсера на одном ответе каждого источника:
по одному запросу, HTML только в RAM. Сравниваются уникальные ID/название/цена/URL по SHA,
в evidence только bool и метрики, без source prose/фото/товарных значений.
Это проверка first page, а не подтверждение полной выгрузки/исторического baseline.

Evidence: audit_evidence/2026-11-02-sc01-dedup/.

Ограничение: устранение дублей не доказывает восстановление прежнего объёма каталога.
Старые baseline/оценки могут по-прежнему отмечать падение числа уникальных товаров;
их не следует сбрасывать автоматически. Задача SC-02 безопасных причин ошибок остаётся отдельно.

Проверка истории версий первоначально выявила неподходящий заголовок пользовательской записи;
он приведён к контракту release_notes, конечный release-набор 5 PASS. Это правка документации,
сборщики к этому моменту уже прошли профильные регрессии. Конечный полный прогон фиксируется ниже.

Конечный полный прогон: 2666 PASS, 1132 subtests, 127 warnings, 172.77 s.
Компиляция и diff-check PASS, secrets findings 0. UI не менялся, browser regression отдельно не повторялся.
Авторская проверка; независимая приёмка и реальные источники фиксируются отдельно после выкладки.

## Подтверждение на стенде

Stand-only bundle без main push: a0caa4f7cfb330fc1611ac0e47eff9714bb7723f, версия 6.18.5.
Healthy, runtime hashes двух адаптеров/version совпали с коммитом; guest admin — только вход,
admin overview 403. Полный settings SHA до/после совпал. Реальные настройки/ключи не сохранялись.

По одному HTTP 200 ответу на каждую прежнюю страницу; старый код взят из 921c33c и исполнен
в отдельном RAM-модуле, новый код — из установленного контейнера. Оба разбирали один и тот же HTML:

| Источник | Строк до → после | Уникальных валидных | Дублей до → после |
|---|---:|---:|---:|
| Moon, охлаждение | 20 → 10 | 10 → 10 | 10 → 0 |
| Вкусмарт, акции | 10 → 5 | 5 → 5 | 5 → 0 |

Множество SHA(ID, исходное название, цена, URL) до/после совпало для обоих источников.
Товарные значения/описания/HTML/фото в evidence не сохранялись; проверялось равенство в памяти.
Данные проб не писались в каталог, полный scan/сброс baseline/рассылки не запускались.
Фоновые задачи стенда работают независимо; оценки истории могут обновиться только после их обходов.
Основной owner UI, полный каталог источников и независимая приёмка этим smoke не подтверждены.
Production не менялся.
