## C2R-01 [P1] Спецификация DDR4-3200 подменяет модель памяти

Место: `product_key.py:248`, `_strong_code` (300–306), `build_key` (360–363).

Регулярное выражение полного кода производителя принимает `DDR4-3200`. Затем найденная строка полностью заменяет извлечённую модель. Два названия с сохранёнными разными моделями `Fury Beast` и `ValueRAM`, одним брендом Kingston, без sku и объёмом 16GB получают один ключ `k2:kingston:ddr43200:16gb`:

- `Оперативная память Kingston DDR4-3200 Fury Beast 16GB`;
- `Оперативная память Kingston DDR4-3200 ValueRAM 16GB`.

Это новая ложная склейка уже на этапе построения ключа, без связи по артикулу или ответа AI. Общая спецификация памяти недостаточна для замены идентичности; если настоящий код расположен позже, поиск также остановится на первой подходящей строке DDR.

Критерий исправления: не распознавать стандарт/частоту/общие характеристики как уникальный код производителя; сохранять различие моделей при отсутствии достоверного кода. Проверить стандарт перед настоящим кодом, отсутствие кода и разные модели с одинаковыми частотой/объёмом, сохранив принятые случаи полного артикула.

## C2R-02 [P1] Сохранённый ключ снимает новую метку BOX при настоящей пересборке

Место: `product_key.py:739–751`; вход из `scripts/migrate_to_k2.py:177–204`.

Проверка совместимости использует собственные новые метки двух BOX-названий и разрешает их связь. Но выбор итогового ключа предпочитает старый `fixed` и проверяет только варианты, не сохранность меток. Поэтому старый ключ без `.box` назначается новому BOX-названию. Несовместимая OEM-группа после этого получает ту же строку ключа, хотя прямую связь BOX↔OEM новая проверка запретила.

Воспроизведение использует настоящие временные SQLite, `title_fields`, `title_articles`, кеш и три предложения: два BOX-названия и OEM той же модели Ryzen 7 7700X. Изначально все имеют прежний `k2:amd:ryzen77700x`. Реальный `run_migration(rescore_only=True, batch_size=1)` оставляет всем этот ключ; все три строки `offers` указывают на один `product_id`. Пачка по одному — допустимый режим и воспроизводимая граница старого/нового состояния. Результат попарного расчёта без старых строк этого не показывает.

Критерий исправления: назначенный ключ должен сохранять собственные обязательные метки и не делать несовместимые группы одинаковыми через устаревший якорь. Повторить с заполненным `title_articles`, различными размерами пачек и порядками, dry-run/resume/повтором; проверить кеш и реальные V2-предложения. Аналогично проверить остальные новые метки.

## C2R-03 [P1] SAME двух OEM-названий переносит третьего участника BOX без полей

Место: `product_key.py:523–541`, вызов через `product_verify._merge_conflict`.

Участник без `title_fields` проверяется по названию только на прежние объём/диагональ, ревизию и готовый компьютер. Новые различия, включая явно написанный BOX, в этот профиль не входят. Старый кеш также может не содержать новых меток.

В реальной временной очереди сравниваются два OEM-названия Ryzen 7 7700X с полями; в группе второго уже находится третье название `AMD Ryzen 7 7700X BOX` без полей. Подменён только внешний ответ проверяющего на корректный для двух OEM `same`. Worker возвращает `resolved`, переносит все три названия на один OEM-ключ и все три предложения на один `product_id`. Отсутствие полей у третьего участника скрывает явное противоречие его названия.

Критерий исправления: перед переносом всей группы учитывать новые различия каждого участника, в том числе без полей и со старым ключом. Для явного BOX↔OEM блокировать перенос всей группы, сохраняя кеш/предложения; покрыть также длины, размеры и новые классовые различия там, где их достоверно задаёт название.

## C2R-04 [P2] Wi-Fi/Flex в поле model и в названии дают несовместимые метки одного товара

Место: `product_key.py:315–319`, запрет связи `712–713`, `keys_conflict:485`.

`.wifi`/`.flex` добавляются только тогда, когда слово отсутствует в извлечённой идентичности. Поэтому один и тот же модификатор, уже включённый моделью в `model`, не представлен в наборе меток. У другого названия того же товара он представлен отдельной меткой. Строгое сравнение наборов объявляет эти представления разными товарами:

- ASRock B850M-X WIFI: `k2:asrock:b850mxwifi` против `k2:asrock:b850mx.wifi`;
- Jabra Evolve2 65 Flex Link380a MS Stereo: `k2:jabra:evolve265flex.link380a.ms` против `k2:jabra:evolve265.flex.link380a.ms`.

В каждом воспроизведении названия описывают одинаковую модификацию, поля отличаются только включением WIFI/Flex в `model`, sku совпадает (для ASRock тестовый). `keys_conflict=True`; даже явный `same` не объединяет пару. Это потеря правильных связей из-за допустимой вариативности извлечённых полей.

Критерий исправления: единое представление модификаторов независимо от расположения в полях; одинаковые варианты связываются по общему коду/подтверждению, разные Wi-Fi/non-Wi-Fi и Flex/non-Flex остаются разделены.
