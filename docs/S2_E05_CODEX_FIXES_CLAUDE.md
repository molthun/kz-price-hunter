## C-E05-01 — неподтверждённый сайт больше не «найденный каталог»

`CATALOG_FOUND` теперь требует `profile.observed`, а не только `tier <= 4`. Профиль, полученный
догадкой по адресу, остаётся `PROFILED` с прямой пометкой «источник не открывался».

Заодно явно определено, **что считается наблюдением**: признаки, которые появляются только при
настоящем обращении — код ответа, тип содержимого, прочитанный образец, — либо явный `observed`
от вызывающего. Догадка по расширению файла наблюдением не является.

```
обычная главная, не открывали → PROFILED
та же, но источник прочитан   → CATALOG_FOUND
```

Существующий тест `test_candidate_catalog_found_for_new_independent_merchant` закреплял прежнее
поведение (`.yml`-адрес без наблюдения считался каталогом) и приведён к новому критерию: теперь он
проверяет **оба** случая — догадку и подтверждённое наблюдение, как и просил аудит.

## C-E05-02 — идентификатор площадки получил пространство имён

Добавлен `normalize_marketplace_id(marketplace, external_id)` с канонической формой `площадка:id`.
Голый номер больше не может быть сильным ключом: это проверяется тем же правилом
`is_weak_identity`, что и для остальных слабых значений, поэтому lookup, частотная защита и
matcher работают с одним форматом.

```
тот же ID на другой площадке (forte:42) → REJECT
тот же ID на той же площадке (kaspi:42) → AUTO_MATCH
голый номер «42»                        → REJECT
```

## C-E05-03 — `observed` переживает запись

Колонка `source_profiles.observed` добавлена аддитивно через `_ensure_column`, пишется и читается.
Round-trip проверен для обоих значений: `True` и `False` возвращаются как записаны.

## C-E05-04 — модерация завершает жизненный цикл, переходы проверяются

Появилась таблица разрешённых переходов `ALLOWED_TRANSITIONS` и функция `transition_allowed`.
`update_candidate_status` отвергает неизвестный статус и недопустимый переход — оба случая
`ValueError` с понятным текстом, а не молчаливая запись.

`CandidateRepository.resolve_candidate_review(queue_id, decision, actor)` закрывает запись очереди
и продвигает кандидата **одной операцией** внутри SAVEPOINT: наполовину применённое решение хуже
непринятого. Повторное решение возвращает `False` и ничего не меняет.

```
до модерации:      REVIEW_REQUIRED, продавец не связан
resolve APPROVED:  IDENTITY_MATCHED, продавец seller_mechta, очередь пуста
повторно:          False
«INDEXED_WITHOUT_APPROVAL» → ValueError: неизвестный статус
IDENTITY_MATCHED → INDEXED → ValueError: недопустимый переход
```
