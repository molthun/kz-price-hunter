# Изолированные проверки кандидата

С 22.11.2026 бывший стенд `kzph-stand` — рабочая бета с пользователями. Использовать его БД для тестов нельзя. Вторую постоянно сканирующую пользовательскую среду не создаём.

## Python-тесты в чистом контейнере

На машине с Docker, из чистого checkout нужного коммита:

```bash
docker build -t kzph-candidate:local .
docker run --rm --network none --tmpfs /app/data:rw,size=512m kzph-candidate:local python -m unittest discover -s . -p 'test_*.py'
```

Сборка требует сети для зависимостей; тестовый запуск — без внешней сети. Не передавать `--env-file` рабочей среды, не монтировать её `data` и не запускать вместо тестов обычный сервер со сборщиками. `tests.test_support` выбирает временные данные до импорта конфигурации.

Для целевого набора:

```bash
docker run --rm --network none --tmpfs /app/data:rw,size=512m kzph-candidate:local python -m unittest tests.domain.test_sizes tests.core.test_settings
```

## Браузер и HTTP

Наборы и необходимые Python/Node/Chrome зависимости описаны в [tests/README.md](../tests/README.md). Используйте предоставленный тестовый сервер с временной БД и fixture-данными. Браузер и приложение должны видеть друг друга на loopback или в отдельной тестовой сети без внешних отправок; браузер не подключается к рабочей бете ради изменения тестовых данных.

VM-тесты JavaScript проверяют логику, но не внешний вид, мобильную вёрстку и computed styles. Изолированный тест не подтверждает реальный AI, Telegram или магазин: такие результаты фиксируются отдельно.

## Репетиция миграции и восстановления

Копию рабочей SQLite получать через backup API, не `cp` активного файла с WAL. Проверять на отдельной копии, исключить реальные токены, отправки и плановый обход. Сохранить исходную копию, проверить quick_check, связи, повторный запуск и сценарий отката. Успешная репетиция не является разрешением менять рабочую БД.

## Передача результата

Указать SHA, версию, образ, команды, итог тестов, найденные ошибки и непроведённые проверки. После принятия — [публикация и обновление](RELEASE_AND_ROLLBACK.md). Git bundle остаётся способом доставки коммитов без push; использовать его нужно для передачи кода, не для сохранения пользовательских данных.
