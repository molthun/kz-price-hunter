## Проверенное поведение

`None` явно обозначает отсутствие предыдущего поиска. Поэтому первый запрос не ждёт независимо
от значения монотонных часов, в том числе при 0. После начала запроса записывается настоящее
время; следующие запросы по-прежнему сериализуются замком и выдерживают заданный интервал
между началами запросов. Недоступный поиск тоже сохраняет паузу до следующей попытки.

Независимый `clock_probe.py` загружает настоящий текущий модуль и исходник `ce70a09` из Git.
Подменяются часы/ожидание/сетевой запрос; функции расчёта паузы и блокировки выполняются настоящие.
БД, реальные поисковики и модели не нужны.

| Сценарий | Результат |
|---|---|
| Часы 0; два запроса | Начала 0 / 90, одно ожидание 90 |
| Часы 30; два запроса | Начала 30 / 120, одно ожидание 90 |
| Большое время работы | Первый без ожидания, второй через 90 |
| Запрос занимает 15 секунд | Следующее ожидание 75 секунд |
| Между запросами уже прошло 100 секунд | Ожиданий нет |
| Явный интервал 0 | Ожиданий нет |
| Запрос возвращает None (недоступен) | Следующая попытка через 90 секунд |
| Три одновременных запроса по 15 секунд | Начала 30 / 120 / 210, ожидания 75 / 75 |

**8/8 PASS.** Контроль 6.7.0 при часах 30 даёт начала 90 / 180 и ожидания 60 / 90:
прежний дефект воспроизведён независимо. Это подтверждает причину лишней паузы в коде;
конкретное время работы старого GitHub runner в этой приёмке не измерялось.
