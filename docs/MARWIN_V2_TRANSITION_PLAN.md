# План перехода «Меломан / MARWIN» с Magento 2 на Next.js API v1 (`v6.42.10`)

Дата: 21.11.2026. Подготовлено Antigravity по замечаниям [аудита Codex](REVIEW_2026-11-21_V64210_CODEX.md) (`MW-01`, `MW-02`).

## 1. Фактическая оценка (только чтение, без персональных данных)

- **Стенд (`kzph-stand`, `prices.db` в режиме `mode=ro`, `PRAGMA query_only=ON`):**
  - активных записей `products` (`shop='Меломан'`): **7 090** (всего `7 090`);
  - записей в `user_favorites` (`item_id LIKE 'marwin_%'`): **0**;
  - записей в `watches` / `watch_state` / `watch_events` (`marwin` / `Меломан`): **0**;
  - 9 старых Magento `source_url` в `source_scans` имеют baseline `319..1433` товаров (старый сайт отдавал 60–150 шт/стр × 10 стр), тогда как новый API `/v1/catalog/products` фиксированно отдаёт **20 шт/стр** (`200` шт за 10 стр).
- **Живые пары legacy → новый API** ([`legacy_id_check.txt`](audit_evidence/2026-11-21-v64210-antigravity/legacy_id_check.txt)):
  - новый API не возвращает прежние Magento `entity_id` (`3661628`, `3655783`, `3632617`);
  - новые `id` (4–6 знаков: `1333`, `1662`, `56255`, `221538`) пересекаются по числовому диапазону со старыми 5-значными Magento ID (`marwin_24909@unknown`).
- **Production (`6.40.33`):** БД прода **не читалась** (граница роли Antigravity). Фактическое число `user_favorites` и `watches` на `marwin_%` в проде должно быть снято read-only перед выкатом `v6.42.10` в прод.

## 2. Безопасная политика перехода (на утверждение владельца)

1. **Изоляция нового поколения (`v6.42.10`):**
   - новый скрапер пишет товары под изолированным ключом **`marwin_v2_<id>@unknown`** и 9 новыми `source_url` (`/knigi-32627` и др.);
   - исключается тихая числовая коллизия и перезапись старых `marwin_<magento_id>@unknown`;
   - новые `source_url` формируют собственные baseline (без ложного `degraded` против старых Magento baseline `319..1433`).
2. **Проверка на стенде (после закрытия живого окна `v6.42.8`):**
   - выложить `v6.42.10` на стенд через git bundle, прогнать полный контейнерный suite;
   - подтвердить рабочий обход всех 9 новых источников, отсутствие коллизий с `marwin_*@unknown` и корректное снятие только при полном обходе со строгой валидацией пагинации.
3. **Управляемая судьба старых Magento-записей (`marwin_*@unknown`):**
   - до отдельного решения владельца старые записи и их история цен **не удаляются и не перезаписываются**;
   - перед выкатом в прод владелец/Claude/Codex снимает read-only срез `user_favorites` и `watches` по `marwin_%` в проде;
   - после подтверждения стабильной работы `marwin_v2_*` владелец утверждает разовую явную деактивацию (`is_active=0` с сохранением истории `price_observations`) для 9 старых Magento `source_url`, чтобы в выдаче не оставались устаревшие Magento-дубликаты.
