# Установка своей копии

Это инструкция для нового владельца установки. Адреса и каталоги действующей беты проекта не нужны для собственного запуска. Используйте свои домен, данные и Telegram-бота.

## Что хранится в Git

Исходники, `requirements.txt`, `constraints.txt`, Dockerfile, compose-файлы, `.env.example`, тесты и документация. При клонировании создаётся пустой каталог: товары придут после обхода магазинов. Пользователи и история чужой установки не переносятся автоматически.

База SQLite, настройки с ключами, токены и резервные копии хранятся вне Git. Для восстановления собственной установки нужны эти данные вместе с соответствующей версией кода. Git не является резервной копией рабочей БД.

## Docker — основной способ

Нужны Git, Docker Engine и плагин Compose v2. На Linux для браузерных сборщиков используйте поддерживаемую Dockerfile архитектуру. Сборка скачивает зависимости и Chromium, поэтому требует интернета и времени.

```bash
git clone https://github.com/molthun/kz-price-hunter.git
cd kz-price-hunter
cp .env.example .env
```

Откройте `.env` в редакторе. Для первого запуска на своей машине:

```dotenv
APP_URL=http://localhost:35539
PUBLIC_ORIGIN=http://localhost:35539
ALLOW_DEV_LOGIN=0
TRUSTED_PROXIES=
TELEGRAM_BOT_TOKEN=
ADMIN_TELEGRAM_IDS=
```

Для публичной установки замените оба адреса на свой HTTPS-origin, без пути. `docker compose` читает `.env` для подстановки в compose. Не коммитьте заполненный файл.

Если сайт раньше открывался по другому адресу, перечислите старые хосты через запятую в `CANONICAL_REDIRECT_HOSTS` (например `CANONICAL_REDIRECT_HOSTS=old.example.kz`). Запросы GET/HEAD к ним получат `301` на `PUBLIC_ORIGIN` с тем же путём и query; пустое значение выключает перенаправление. Если перед приложением стоит прокси, он должен сам задавать `X-Forwarded-Host`, а его адрес должен быть в `TRUSTED_PROXIES`.

```bash
docker compose up -d --build kz-price-hunter
docker compose ps kz-price-hunter
curl --fail http://localhost:35539/api/version
curl --fail http://localhost:35539/api/health
docker compose logs --tail 50 kz-price-hunter
```

Сайт — [http://localhost:35539](http://localhost:35539). Данные сохраняются в `./data`, смонтированном как `/app/data`. Не запускайте просто `docker compose up -d`: общий файл также содержит необязательный Watchtower. Для воспроизводимого обновления используйте явную версию и обновляйте приложение вручную.

Перезапуск и остановка:

```bash
docker compose restart kz-price-hunter
docker compose stop kz-price-hunter
```

Остановка не удаляет `./data`. Для обновления сначала сделайте согласованную резервную копию, затем следуйте [порядку выпуска](RELEASE_AND_ROLLBACK.md).

## Telegram, доступ и AI

- Создайте своего бота у BotFather. Укажите его токен в локальном `.env`, а числовые Telegram ID администраторов — в `ADMIN_TELEGRAM_IDS`. После смены этих переменных пересоздайте приложение командой `docker compose up -d --force-recreate kz-price-hunter`.
- Для публичного входа и Mini App нужен HTTPS и домен, настроенный для вашего бота. Пустой токен отключает Telegram-вход и уведомления; сервис не получает чужого бота из репозитория.
- Гостевой доступ по умолчанию ограничен политикой установки. Полное управление требует администратора. Параметры см. в [настройке доступа](../SECURITY_CONFIG.md) и [руководстве бота](TELEGRAM_BOT.md).
- Для локальной LLM задайте собственный доступный приложению endpoint и модель в настройках. `localhost` внутри контейнера — сам контейнер, а не GPU-хост. Ключи платных провайдеров не обязательны для запуска базового приложения и не поставляются с кодом.

## Домен и reverse proxy

Настройте HTTPS-прокси на порт 35539 приложения и одинаковые `APP_URL`/`PUBLIC_ORIGIN` для канонического адреса. Доверяйте только проверенному адресу непосредственного прокси; полный порядок — [SECURITY_CONFIG.md](../SECURITY_CONFIG.md).

Два домена, ведущие на один порт, используют один сервер, но остаются разными browser origin. Для беспроблемного входа и POST-запросов второй домен лучше перенаправлять на основной с сохранением пути и query. Смена порта назначения не создаёт HTTP-редирект.

## Python — запуск из исходников

Нужен Python 3.14, как в CI и Dockerfile. На Linux Chromium могут потребоваться системные библиотеки Playwright.

```bash
python3.14 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt -c constraints.txt
python -m playwright install chromium
mkdir -p local-data
DATA_DIR="$PWD/local-data" PORT=8080 ACCESS_MODE=open APP_URL=http://localhost:8080 PUBLIC_ORIGIN=http://localhost:8080 python gui.py
```

Откройте [http://localhost:8080](http://localhost:8080). Здесь данные постоянные в `local-data`, а не во временном каталоге. Прямой Python-запуск требует переменных окружения процесса: наличие `.env` само по себе не обещает их загрузку. Этот запуск слушает сетевые интерфейсы; не публикуйте отладочную установку в интернете.

## Проверка установки и сохранение данных

Версия и health должны отвечать 200. На пустой базе отсутствие товаров до обхода нормально. Проверьте один обычный плановый сбор, затем поиск и карточку. Для восстановления существующего каталога используйте SQLite backup API и [инструкцию восстановления](OPERATIONS.md#резервная-копия-и-восстановление).

Если приложение не запускается: проверьте журнал, свободный порт, права на `./data`, валидность origin и доступность источников. Не удаляйте БД ради исправления конфигурации.
