# Telegram и уведомления: перенос в новую админку

02.11.2026, Codex по прямому поручению владельца. База 7690327, версия 6.18.3.
Один пишущий агент, чужие untracked сохранены. Production и main push не входят в работу.

## Поведение

В `/admin#telegramTool` собраны три независимых состояния: подключение бота, приём команд,
очередь доставки. «Токен задан» не означает успешного подключения или доставки сообщения.
Проверка вызывает только getMe, без getUpdates/sendMessage и без изменения токена.
Время и результат последней проверки видны; при смене токена старый результат сбрасывается.

Приём команд получает RAM-отметки из существующего polling loop: успех, конфликт, отказ токена,
сетевая ошибка, остановка. Свежесть — 120 секунд, последний успешный опрос показан отдельно.
После перезапуска история отметок начинается заново. Это не время доставки сообщения:
достоверной общей метки доставки в существующей очереди нет, интерфейс прямо это сообщает.
Счётчики относятся к сохранённой очереди, а не ко всей истории работы.

Суточная сводка администраторам имеет отдельную узкую форму: включение и час 0–23.
Часовой пояс отображается из существующих настроек; личные уведомления/получатели не меняются.
Сохранение разрешает существующую плановую доставку, но само не создаёт тестовых сообщений.
Revision учитывает оба изменяемых поля и часовой пояс; CAS под settings write lock защищает
от устаревшего часа после изменения часового пояса. Остальные параметры не перезаписываются.
Старая панель содержит ссылку на новый раздел; прежний monitoring API сводки совместим.

## Локальный ИИ

При первом открытии раздела и после проверки подключения запускается разбор локальной моделью.
Передаются только подтверждённые коды проблем и обезличенные логические признаки состояния.
Токены, адрес локального сервера, имена/ID пользователей, username бота и сырые ошибки в prompt
не попадают. Модель расставляет порядок устранения причин; принимается только перестановка
полного набора подтверждённых кодов. Описания и действия берутся из проверенного словаря:
модель не придумывает ошибки, команды, получателей или изменения настроек.

Используется call_local_api, без платного fallback, с соблюдением паузы модели и общего слота.
Одновременные запросы ограничены, успешные результаты кешируются в RAM на 120 секунд;
ключ кеша учитывает факты и фактическое подключение использованной модели. HTTP rate limits:
getMe — 3/мин, разбор — 6/мин. При отказе/занятости ИИ остаются подтверждённые действия.
Запоздавший ответ ИИ после сохранения/обновления состояния не применяется к новому состоянию.

## Проверки и ограничения

Тесты используют временные settings/БД и подставленные Telegram/AI ответы. Рабочая БД,
реальные настройки и токены не изменялись. Новая форма проверена в Chrome 390/1366,
в светлой и тёмной темах: drafts, нулевой час, scoped save, повторные нажатия, 409,
refresh/reload, auto local diagnosis и запоздавший ответ. Физический Safari/телефон и основной
owner login отдельно не проверены. Авторская проверка не заменяет независимую приёмку.
