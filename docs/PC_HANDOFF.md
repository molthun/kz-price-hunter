## Действия помощника на Windows

1. Клонировать репозиторий в новую свободную папку, например E:\Dev\kz-price-hunter.
   Не использовать папку проекта E:\AI и не перезаписывать существующий checkout.
2. Получить ветку `dev/pc-handoff-20260925`, проверить HEAD и чистоту рабочего дерева.
3. Прочитать AGENTS.md, docs/DEVELOPMENT_PLAN.md, docs/AGENT_HANDOFF.md и этот файл.
4. Для конкретной порученной задачи создать собственную ветку `pc/<название-задачи>`
   от ветки передачи. Не писать в main и не отправлять релизные теги.
5. Проверить Git, Python и доступ к LM Studio. Используемая на Маке и в CI версия
   Python — 3.14; создать отдельное виртуальное окружение проекта. Не менять окружения AI.
6. Подключить выбранный владельцем инструмент для редактирования кода к локальному API
   LM Studio. Само клонирование репозитория не подключает локальную модель к агенту.
7. Пока задача на код не назначена: только подготовка окружения и отчёт о готовности.
   Полномочия следующих этапов не следуют из исторических карточек передачи.

## Данные и проверки

settings.json, .env, рабочие базы, резервные копии и ключи с Мака не передаются.
Работать с временными тестовыми данными и пустыми внешними credentials.
Не запускать production scraping, рассылку, миграции рабочей БД или платные API.
Базовые проверки: `python -m unittest test_seller_matcher test_dual_write`
и `python release_gate.py secrets --root .`.

Свежая проверка снимка на Маке: 21 тест OK, Python 3.14.7, временный DATA_DIR,
секретные переменные окружения очищены, внешние socket.connect заблокированы.
Сканер секретов проекта: находок нет. Полный regression suite и Windows в этой
передаче не проверялись. Исторические результаты в аудитах не являются новым прогоном.

## Возврат результата

В отдельной ветке: небольшой коммит, описание изменённых файлов, команды и результаты
проверок, точный HEAD, ограничения. Обновить карточку передачи своей задачи.
Отправить только свою ветку, сообщить её имя владельцу. Слияние с main и релиз отдельно.
По текущим workflows push в main и релизные теги запускают процесс публикации образа.
Google Drive можно использовать для отчётов; исходники передавать через Git.
