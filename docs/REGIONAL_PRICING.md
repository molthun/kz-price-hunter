# Региональные цены, наличие по городам и доставка по Казахстану

> Зафиксировано 19.11.2026 по результатам проверки реальных цен и наличия в магазинах Казахстана (пилот `v6.41.0`).
> Связанные документы: [архитектура](ARCHITECTURE.md), [план развития](DEVELOPMENT_PLAN.md), [стандарт адаптеров](../SCRAPER_STANDARD.md), [реестр источников](../SOURCES.md).

## 1. Проблема (фактические реалии рынка РК)

У многих ритейлеров Казахстана **один и тот же URL товара** отдаёт разные цены и разное наличие в зависимости от выбранного города:

- **Пример `12.kz` (19.11.2026):** «Радиатор алюминиевый UNO Алюрад 500/100» (арт. `0575073`, единый URL) стоил **27 300 ₸ в Алматы** (`current_region=471567`, 14 шт.) и **35 000 ₸ в Астане** (`current_region=471565`, 6 шт.) — разница **+28% (7 700 ₸)**.
- **Пример «Белый Ветер» (`shop.kz`):** официальный YML-фид (`yandex.php`) содержит весь каталог с доставкой по Казахстану, но наличие распределено по филиалам в разных городах. Ранее все позиции из YML сохранялись с `city="Астана"`, из-за чего пользователи из Алматы, Шымкента и других городов не видели их при фильтрации по городу.

Если обходить такие магазины только под одним городом или смешивать цены разных городов в одной записи:
1. Пользователь в другом городе видит ложную цену и сталкивается с другой суммой на кассе.
2. История цен и расчёт скидок ломаются (скачки 27 300 ₸ ↔ 35 000 ₸ выглядят как «супер-скидка -22%»).
3. Предложения с доставкой по Казахстану пропадают из выдачи в соседних городах.

## 2. Три класса региональности источников

В `config.py` (`SHOP_REGIONAL_POLICY`, `get_shop_regional_policy`) каждый активный магазин из `SHOP_KEYS` отнесён к одному из трёх классов:

| Класс (`mode`) | Смысл | Стратегия обхода | Как хранится и показывается |
|---|---|---|---|
| `multi_city_price` | Разные цены и/или локальное наличие в разных городах РК (`12.kz`, `Kaspi`, `Technodom`, `Sulpak`, `Mechta`, `DNS`, `Комфорт`, `Magnum`, `Arbuz` и др.) | Обход отдельно по приоритетным городам (`target_cities`, базово **Алматы + Астана**) с передачей cookie / заголовка / slug города и проверкой фактического города в ответе | Раздельные записи `id@almaty` и `id@astana`, независимая история цен и алерты строго внутри одного города |
| `delivery_kz_multi_stock` | Федеральная цена или общий фид, но склады/филиалы в разных городах + доставка по РК (`Белый Ветер / shop.kz`, `Alser`, `Evrika`, `Kari`, `Zeta`, `Планета Электроники`) | Не дублировать тяжёлый обход по 15 городам: базовый фид/обход даёт актуальную цену с доставкой по РК (`city="Астана / Казахстан"` / `"Казахстан"` → `@kz`); городское наличие при необходимости подтягивается отдельно | Видно во всех городах РК (`o.city LIKE '%Казахстан%'`) с явным указанием региона/доставки |
| `single_price_kz` | Единая цена по всему Казахстану с центрального склада (`iSpace`, `Marwin`, `Flip.kz`, `KIMEX`, `Французский Дом`, `Intertop`, `Askona` и др.) | Обход 1 раз | `id@kz` (или базовый город с доставкой по РК), показывается во всех городах |

## 3. Архитектурные инварианты

1. **Идентичность по городу (`offer_identity.py`):**
   - `offer_id(product)` формирует составной ключ `<prefix>_<raw_id>@<location_slug>`:
     - `Алматы` → `@almaty`
     - `Астана` → `@astana`
     - `Казахстан`, `Астана / Казахстан`, `Алматы / Казахстан`, `Все регионы` → `@kz`
   - Разные города одного товара никогда не перезаписывают друг друга и имеют независимую `offer_price_history`.
2. **Подтверждение города в ответе скрапера:**
   - Адаптер класса `multi_city_price` обязан проверять, какой город фактически отдал сайт. Цена принимается только при **положительном** подтверждении: отсутствующий, пустой или чужой маркер города — ошибка разбора страницы (`error_code=parse`), цена не записывается, обход категории неполный (6.41.4, R1-A01).
   - Где маркер есть (проверено живыми ответами 19.11.2026): `12.kz` — `.regions__name`; `technodom.kz` — `__NEXT_DATA__ … initialState.core.currentCity.slug`; `sulpak.kz` (HTML-каталог) — все атрибуты `data-city-id` равны запрошенному `city_id`. Страница без карточек маркер не требует: цен она не записывает.
   - Где ответ город не возвращает (город задаётся только параметром запроса): Kaspi (`c` + `X-KS-City`, JSON без поля города), Magnum (`?city=`, JSON без поля города), JSON-выдача распродажи Sulpak. Mechta с адреса проверки отвечала 403, наличие маркера не установлено. Для этих источников подтверждение остаётся открытым риском R1.
3. **Безопасная сверка `reconcile_source` при мультигородском обходе:**
   - Если скрапер обходит категорию по нескольким городам (`TwelveMonthsScraper._scrape_sync` по `DEFAULT_CITIES = ("Алматы", "Астана")`), сессия сбрасывается между городами (чтобы `PHPSESSID` не кэшировал старый регион), результаты объединяются в один `ScanResult`, а `complete=True` выставляется **только если все города завершились полностью без ошибок**.
   - При сбое одного города общий `complete=False`, поэтому `reconcile_source` не помечает товары остальных городов снятыми с продажи.
   - Объединение выполняет общая `scrapers.base.merge_city_results` (Kaspi, Magnum, Technodom, Sulpak, Mechta, 12.kz): `unparsed` суммируется, `limited` наследуется, `error_info` берётся у первого сбойного города, текст `error` перечисляет все города (6.41.4, R1-A03).
   - Карточка, которую адаптер видел, но не разобрал (сломан селектор цены, названия, ссылки), считается в `unparsed` и запрещает `complete`; карточка «Нет в наличии» — подтверждённое отсутствие, не ошибка (6.41.4, R1-A02).
   - `assign_offer_ids(prods)` выполняется до `data_quality.dedupe(prods)`, поэтому пары `twelve_months_<id>@almaty` и `twelve_months_<id>@astana` сохраняются обе.
4. **Честная выдача и уведомления:**
   - Скидки, аномалии и ценовые наблюдения (`watches`) сравнивают цену **только внутри одного `offer_id` (одного города)**.
   - В поиске по городу (`repositories/search_repo.py`) показываются предложения выбранного города плюс общеказахстанские предложения с доставкой (`o.city LIKE '%Казахстан%'`).

- **R1-01 (`v6.41.0`, пилот):** реестр `SHOP_REGIONAL_POLICY` в `config.py`, исправление `offer_identity.py` (`Алматы / Казахстан` → `@kz`), перевод `12.kz` на актуальную платформу Bitrix Aspro Premier с мультигородским обходом **Алматы + Астана** и проверкой `.regions__name`, перевод YML Белого Ветра (`shopkz`) на `Астана / Казахстан` (`@kz`) для видимости во всех городах РК.
