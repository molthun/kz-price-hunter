# SSD / HDD / оперативная память: исправление разделов

02.11.2026, Codex по прямому поручению владельца. Версия 6.15.8, только стенд.
Исходное состояние: SSD `storage` объединял HDD/RAM aliases; RAM из Forcecom ошибочно
поступила с меткой SSD и была закреплена как feed. ИИ пропускал закреплённые карточки.

## Изменения

- Сохранены имя и адрес SSD `storage`. HDD — новый `hdd`; оперативная память — прежний `ram`.
  Флешки и карты памяти вынесены в `removable_storage`.
- Удалены пересекающиеся aliases, HDD/карты/флешки разделены в сопоставлении прямой выгрузки.
  Неоднозначный раздел «USB внешние накопители» не объявляется флешками автоматически.
- Явный тип названия проверяется до метки магазина. Ноутбуки, компьютеры, платы, видеокарты
  и аксессуары не становятся RAM/диском из-за упоминания характеристик/совместимости.
  Карта с адаптером остаётся картой, диск с металлическим корпусом остаётся диском.
- Старые автоматические закрепления в семействе памяти/накопителей пересматриваются.
  Голый артикул переносится только при единственном согласованном явном разделе активных источников.
  Нераспознанные названия не распределяются по догадке.
- Точный ID категории разрешается до fuzzy aliases: новый removable_storage не попадает в SSD.
- Переносятся category и автоматический verdict; цены, canonical ID, предложения и наблюдения сохраняются.

## Проверки до выкладки

- Профильный набор текущего кода: 316 PASS + 244 subtests.
- Финальный полный прогон: **2579 PASS + 1120 subtests**, 158.28 s; frontend 4/4 (390/1366, обе темы).
- Воспроизведение AMD Radeon UDIMM; HDD/SSD/DDR/DIMM, карты с адаптерами, флешки;
  ноутбуки/компьютеры/платы/аксессуары; старый feed pin; повторное применение и повторный сбор;
  отдельные результаты поиска по ID категории; сохранность цен/offer links.
- В тестах временные БД; реальные внешние AI/Telegram не вызываются.
- На стенде hardware intent/expansion записей нет, активных expansion заданий нет.

## Выкладка и применение

Стенд `2bec6d6`, 6.15.8, healthy; хэши runtime совпали с локальным кодом.
Только bundle; push/main и production не менялись.

При остановленном стенде создан sanitized snapshot `before-storage-split-6158-sanitized.db`,
quick_check PASS. Синхронизированы 4 категории; feed исправил 135 назначений,
адресная проверка старых pins — ещё 274: **409 назначений**. Все остальные поля товаров,
предложений, цен, наблюдений, пользователей, intent/expansion metadata остались прежними —
проверены полными контрольными суммами. Повторные feed + repair не возвращают неправильный раздел.
Описания остаются нулевыми. Canonical ID и связи предложений не менялись.
