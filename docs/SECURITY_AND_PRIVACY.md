# 🔒 Безопасность и приватность данных (Security & Privacy)

## 1. Аутентификация и авторизация

### Telegram Login Widget
Вход пользователей в систему осуществляется через официальный виджет Telegram Login Widget:

1. **Проверка криптографической подписи (HMAC-SHA256)**:
   - Входные данные виджета сортируются в алфавитном порядке и объединяются в строку вида `k=v\n`.
   - В качестве секретного ключа используется `SHA-256(bot_token)`.
   - Вычисляется `HMAC-SHA256(secret_key, data_check_string)`.
   - Сравнение с переданным параметром `hash` производится через константно-временное сравнение `hmac.compare_digest()`, защищающее от атак по времени (timing attacks).

2. **Защита от устаревших данных (`auth_date`)**:
   - Время авторизации проверяется сервером: если `time.time() - auth_date > 300` (более 5 минут), авторизация отклоняется.

3. **Управление сессиями**:
   - Токен сессии генерируется криптографически стойким генератором `secrets.token_urlsafe(32)`.
   - Сессия сохраняется в таблице `user_sessions` со сроком действия 30 дней.
   - Cookie сессии передаются с обязательными флагами безопасности:
     - `httponly = True` (защита от чтения cookie через JavaScript/XSS).
     - `samesite = "Lax"` (защита от межсайтовой подделки запросов CSRF).
     - `secure = True` (при работе через HTTPS).
   - При старте сервера вызывается `cleanup_expired_sessions()`, удаляющая истекшие сессии из базы данных.

4. **Разделение прав доступа (RBAC)**:
   - **Гость**: доступ только на чтение общедоступных цен и каталога.
   - **Авторизованный пользователь**: управление личными порогами аномалий, фильтрами магазинов, Telegram-алертами.
   - **Администратор** (ID указан в `ADMIN_TELEGRAM_IDS`): системные настройки сканирования, запуск ручного обхода, просмотр логов, блокировка пользователей.

## 2. Заголовки безопасности HTTP (Security Headers)

`auth_middleware` в `auth.py` автоматически внедряет стандартные HTTP-заголовки безопасности во все серверные ответы:

```http
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
```

- **`X-Content-Type-Options: nosniff`**: предотвращает MIME-sniffing браузером (интерпретацию текстовых файлов как исполняемых скриптов).
- **`X-Frame-Options: DENY`**: блокирует встраивание интерфейса в `<iframe>` на сторонних сайтах, защищая от атак типа Clickjacking.
- **`Referrer-Policy: strict-origin-when-cross-origin`**: предотвращает утечку путей URL во внешние сервисы при переходе по ссылкам.

## 3. Безопасность Telegram-алертов

Перед отправкой уведомления с изображением товара модуль `notifier.py` выполняет валидацию URL:
- Разрешены исключительно протоколы `http://` и `https://`.
- Недопустимы потенциально опасные схемы (например, `file://`, `javascript:`, `data:`).
- При недопустимом или отсутствующем URL алерт отправляется без фотографии в виде безопасного текстового сообщения.

## 4. Минимизация данных и AI-приватность (Data Minimization)

Проект использует внешние нейросетевые модели (Google Gemini Flash REST API и OpenAI REST API) для умного разбора поисковых запросов и ассистента-консультанта:

- **Что уходит AI-провайдеру** (Gemini, OpenAI или совместимый сервис — по настройкам владельца):
  - текст поискового запроса или вопроса консультанту **как его ввёл пользователь**, ограниченный контекст текущего диалога, выбранный город и подобранные карточки товаров из каталога (название, магазин, цена, характеристики);
  - при фоновой нормализации — названия товаров из каталога.
- **Что не добавляется в запросы к AI**: профиль Telegram (ID, username, имя), IP-адрес, cookies, история входов. Отдельного добавления этих данных в промпт в коде нет.
- **Чего проект не гарантирует**: анонимизации свободного текста. Если пользователь впишет в вопрос имя, телефон или адрес, это уйдёт провайдеру как есть. Поэтому интерфейс и страница `/privacy` просят не вводить лишние личные данные. Обработка на стороне провайдера определяется его условиями.
- **Ответ AI — недоверенные данные**: проверяется формат и длина, карточки товаров берутся только из БД; дневной лимит числа вызовов (`AI_DAILY_CALL_LIMIT`) — это ограничение количества, а не денежный бюджет.
- **Изоляция сетевого стека**:
  - Взаимодействие с API моделей ведется напрямую через асинхронный HTTP-клиент `aiohttp` без использования сторонних тяжелых SDK, собирающих аналитику.

## 5. Административные разделы и AI-задачи проекта

### Что доступно только администратору

`/monitoring` и все `/api/admin/*` закрыты декоратором `require_admin`: без входа — 401, у обычного
пользователя — 403. Это относится и к разделам, добавленным последними этапами: помощник администратора,
суточная сводка и её отправка в Telegram, переключатели включения планировщика и AI-части сопоставления.

### Помощник администратора (P12) — только чтение

- Список инструментов закрытый; каждый инструмент только читает отчёты мониторинга. Тест проверяет
  исходный код инструментов на отсутствие любых команд записи (`INSERT`, `UPDATE`, `DELETE`, `record_`,
  `spawn_scan`, `backup_database`), поэтому «помощник ничего не меняет» — это свойство кода, а не обещание.
- В модель уходят только собранные цифры и вопрос администратора. Ответ с числом, которого нет в данных,
  не показывается: вместо него — сводка фактов и причина отказа.
- Названия магазинов и категорий приходят со сторонних сайтов и подаются в промпт как размеченные данные
  с прямым указанием не выполнять инструкции изнутри.

### Суточная сводка в Telegram (P13)

- Отправка выключена по умолчанию и включается владельцем; получатели — только администраторы
  (`ADMIN_TELEGRAM_IDS`), заблокированный администратор получателем не является.
- Письмо уходит один раз за сутки: задание идёт через общую очередь уведомлений в своём пространстве
  идентификаторов, и `UNIQUE(alert_id, user_id)` не даёт продублировать его при перезапуске или повторной
  проверке. Письмо человеку, переставшему быть администратором, отменяется, а не доставляется.
- Содержимое — агрегированные цифры сервиса. Персональных данных пользователей в сводке нет.

### AI-часть сопоставления каталога (P09)

- Модели показываются только два названия товаров из каталога магазинов — в блоке размеченных данных.
  Пользовательских данных в этом запросе нет.
- Полномочия модели ограничены кодом: пара с явным противоречием ей не показывается, уже принятое
  правилом решение не пересматривается, а вердикт может только разрешить сравнение, но не запретить.
- Режим по умолчанию — «выключено»; включение и переход в рабочий режим — решение владельца, опирающееся
  на пороги, согласованные до замеров.

### Секреты

- Значения ключей и токенов не показываются в интерфейсе: видно только «настроено» или «нет».
- Шлюз выката (`release_gate.py secrets`) ищет в исходниках то, что выглядит как настоящий ключ, и
  останавливает публикацию образа. Сам секрет в отчёт проверки не попадает — только вид и длина.
