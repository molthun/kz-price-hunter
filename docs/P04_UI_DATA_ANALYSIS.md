## План исправлений (P04)

1. **U01–U03 — одно определение для каждого счётчика.**
   - `/api/stats?city=` считает акции той же функцией, что и витрина (`get_store_deals(...)["total"]`, общая склейка и свежесть), а аномалии и арбитраж — по городу.
   - Результат кэшируется на короткое время и сбрасывается вместе с `invalidate_alerts_cache`.
   - `loadStats` передаёт текущий город.
   - Бейджи вкладок пишет только `loadStats`. Списки показывают свои «Показано N из M» и при совпадающих фильтрах дают то же M.
   - Регрессия: `stats(city).total_store_deals == deals(city, type=all).total`; аномалии — `== len(alerts(anomaly, city))`.
2. **U04 — проверка ответа.** Проверять `res.ok` и форму данных; при ошибке показывать состояние «Не удалось загрузить» с кнопкой «Повторить», бейджи не трогать. Frontend-регрессия на ошибку API.
3. **U05, U06, U07 — вёрстка.**
   - U05: строка разбивки переносится по пунктам без выхода за край.
   - U06: на узком экране показывать 10 иконок и «+N».
   - U07: ряд вкладок с `flex-wrap` на широких экранах.
   - Проверка на 390 / 768 / 1366 / 1920 px.
4. **U08 — первый шаг модуляризации.**
   - Общие функции форматирования (`fmtPrice`, `escapeHtml`, свежесть) вынести в `web/static/js/format.js`: отдаётся сервером и подключается до основного скрипта.
   - Frontend-тесты учатся отдавать `/static/*`.
   - Новый `test_frontend_format.cjs` проверяет модуль.

Проверки после исправлений: полный Python suite, все `test_frontend*.cjs` (Deno), визуальная проверка в браузере на четырёх размерах.
