# SC-03: действующие и исторические категории источников

02.11.2026, Codex по поручению владельца «Дальше по плану». База d61ade5, версия 6.18.7.
Один исполнитель, чужие untracked сохранены. Только стенд, без production/main push.

## Подтверждённая причина

Свежий снимок SC02 показал 5 typed timeout категорий Forcecom/Europharma: диагностика работает,
но таймаут сам по себе не доказывает дефект разбора. При проверке пустых категорий Alser обнаружено,
что удалённые адреса уже отсутствуют в config: в нём 6 категорий. Мониторинг при этом выбирал
последние результаты всех 13 URL, когда-либо записанных в source_scans. Проверка на стенде:
13 наблюдаемых/11 проблемных против 6 действующих/4 проблемных, 7 прежних адресов.
Число проблем меняется со штатными обходами; число прежних адресов подтверждено отдельно.
Повторно возвращать удалённые адреса или чинить их парсер без основания не требуется.

## Изменение

В current overview передаётся явный список URL категорий из SHOP_REGISTRY. По нему фильтруются
текущие category counts, качество, сумма baseline и структурированные подсказки причин.
Количество текущих категорий соответствует уникальным URL. Старые rows не удаляются/не изменяются.
Карточка магазина применяет свой переданный список категорий; история обходов, события и инциденты
остаются историей. В новой админке отдельно видно число прежних наблюдавшихся категорий.
Вызовы без explicit scope совместимы с прежним контрактом; основные UI/API получают scope явно.

Новая админка, прежний overview, detail и инструмент состояния магазинов помощника администратора
используют один действующий реестр. Помощник больше не передаёт фиктивное число категорий 0.
Локальный помощник получает уже отфильтрованные факты, архивная причина не превращается
в текущую рекомендацию. Платные API/модели не настраивались.

Если по новой/заменённой категории нет наблюдений, оценка unknown; при смешении known/unknown
общая оценка магазинов не становится healthy. Реальные failed/degraded категории сохраняются.
Существующие пороги тяжести не меняются: один сбой небольшой категории может давать limited,
а не degraded. Общий фактический неудачный итог последнего обхода магазина остаётся видимым:
фильтрация старых категорий не переписывает его в успех до нового достоверного обхода.
Выключенные магазины остаются disabled. Категории текущей волны не подменяют полный реестр.

Изменяется только чтение/представление. Реестр URL, сборщики, каталог, baseline, quality thresholds,
расписание и settings не менялись. Новых сетевых запросов к магазинам для этого исправления не требуется.
