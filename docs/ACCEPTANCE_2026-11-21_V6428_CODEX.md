- Один ответ API разбирается для Астаны и Алматы, дополнительного запроса для второго города нет. Отсутствие городской цены сохраняет fallback «Казахстан» без повторного общереспубликанского предложения.

- Независимый двухстраничный сценарий: 101 товар даёт 202 предложения, 101 для каждого города, запросы страниц строго `[1, 2]`. Добавление сломанной карточки на последнюю страницу сохраняет 202 предложения, но даёт `unparsed=1`, `limited=True`, `complete=False`.
- Это синтетические проверки. Реальный Forte API и рабочие результаты нового контейнера в этой сессии не проверялись; авторский live smoke не выдаётся за независимый.

### 6.42.8 — добор источников

- Последний обход выбирается отдельно для пары магазин/URL. Обычный источник отстаёт после круга плюс волна; горячий и общий фид — после двух волн; failed/degraded повторяется не раньше 600 секунд. Выключенные категории и магазины на паузе исключаются.
- Добор передаёт только выбранные URL в `_scan_shop`; не входит в блок продвижения `wave_index`, `wave_cycle`, `wave_last_run_at` и записи результата плановой волны. Штатные поведенческие тесты этого пути проходят.
- Независимо исполнен один настоящий цикл `auto_scan_background_worker` с подменой часов, ожидания, запуска задач и входных снимков: наступившая плановая волна имеет приоритет и не вызывает планировщик добора; между волнами передаётся точный словарь URL; при занятом сканере не запускается ни один путь.
- Независимая интеграция настоящих `record_shop_scan_result`, `get_source_last_scans`, `get_shop_scans` и `_catchup_sources` на временной SQLite: пять последовательных отказов допускают повтор через **600, 600, 1200, 2400, 3600 секунд**. На секунду раньше каждого порога добор запрещён. Первые два интервала ограничены 10-минутным минимумом источника, последующие — backoff магазина.
- Эти результаты подтверждают локальные решения планировщика, но не длительность реальных обходов, фактическую свежесть всех источников или отсутствие перегрузки при большом первоначальном доборе.
