## G2 · Сохранность истории отката после partial и продолжения

Существующий отчёт теперь отклоняется; первоначальная запись плана создаёт новый
файл без замены существующего. Для продолжения нужен новый путь отчёта.

Независимое CLI-воспроизведение на **450** искусственных товарах:

1. Trigger вызывает ABORT во второй пачке. Первый запуск возвращает **4**,
   `status=partial`: полный план 450, фактически применено 200.
2. Повтор в тот же отчёт возвращает **2**; первый файл сохраняется побайтно.
3. Продолжение в новый отчёт возвращает **0**, применяет оставшиеся 250.
   Первый отчёт не меняется.
4. Два сохранённых отчёта содержат исходные model и фактические applied-ID для
   **450/450** товаров.
5. Независимый обратный UPDATE только по этим отчётам восстановил model всех 450
   строк в искусственной БД. Это проверка достаточности артефактов для данного
   отката, а не реализация отдельной пользовательской команды rollback.
