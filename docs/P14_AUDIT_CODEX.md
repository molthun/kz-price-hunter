## K01 — P2: порог бэкапов предполагает периодического работника, которого в снимке нет

Место: `environment.STALE_AFTER_SECONDS[BACKUP]`, `enabled_components`, `database._record_backup`, вызовы backup_database.
BACKUP всегда enabled, heartbeat обновляется только при вызове backup_database; в проверенном production-коде вызовы привязаны к миграциям/подготовке обновления схемы. Периодического ежедневного работника нет. Через 48 часов без миграции система объявляет компонент молчащим, хотя ожидаемая задача ему не назначена. Тест порогов предполагает ежедневный бэкап, не проверяя существование расписания.

Подтверждение: поиск production-вызовов backup_database показывает только пути миграций; запись успешного heartbeat в NOW и `component_state(BACKUP, ..., True, NOW+49h)` → **stale**. Это не свидетельство гибели фонового работника.

Рекомендация: разделить возраст последней резервной копии и liveness реально запущенного worker. Если расписание не настроено, явно показывать это; не добавлять автоматические операции backup в рамках исправления без соответствующей задачи. Если периодический worker реализован последующим этапом, проверить его отдельно вместе с интервалом и условиями запуска. Приёмка: отсутствие настроенного расписания, успешный штатный цикл, просрочка реально ожидаемого цикла и ошибка создания копии различаются.

## K02 — P2: отключённая телеметрия распознаётся как включённая

Место: `environment.enabled_components` и `telemetry.telemetry_enabled`.
Рабочий компонент принимает TELEMETRY_ENABLED=0/false/no/off (без учёта регистра), но environment проверяет только != '0'. Для допустимого значения false мониторинг ждёт heartbeat намеренно выключенного компонента и показывает unknown/stale вместо disabled.

Независимое воспроизведение: `patch.dict(os.environ, {'TELEMETRY_ENABLED':'false'})` → **telemetry.telemetry_enabled() == False**, **environment.enabled_components()['telemetry'] == True**. Аналогичное расхождение следует для no/off и регистра.

Рекомендация: использовать ту же функцию включения, что и компонент. Приёмка: все поддерживаемые формы env дают одинаковое решение worker и мониторинга; отключённый компонент не ухудшает состояние системы после истечения порога.
