## C01 — P1: дубли обходят проверку объёма и позволяют снять реальный каталог

Место: `data_quality.py:54–61` (`measure`), `web/server.py::_scan_shop_categories`, `database.py::reconcile_source`.

`valid` считает строки, а снятие товаров работает по идентификаторам. Поэтому 200 строк одного и того же предложения выглядят как нормальные 200 товаров. Воспроизведено сквозным вызовом `_scan_shop_categories` с временной БД: три полных результата по 200 уникальных товаров сформировали baseline=200; затем complete-результат из 200 копий одного товара получил **quality=ok, valid=200, accepted=1**. В каталоге остался **1 активный товар вместо 200**. Защита от тихой поломки не сработала.

Рекомендация: считать объём по уникальной нормализованной идентичности предложения (после assign_offer_ids), отдельно учитывать received/duplicates/rejected. Согласовать дедупликацию между оценкой качества, сохранением и reconcile. Конфликтующие копии одного ID не должны незаметно определять цену по последней строке. Неполный/деградировавший результат не обучает baseline и не снимает отсутствующие предложения.

Приёмка: baseline 200 уникальных → 200 повторов одного ID даёт degraded и сохраняет все 200 активных записей; добавление дублей не увеличивает норму; одинаковые товары разных магазинов/городов не склеиваются. Проверить реальный pipeline, а не только measure. Тест повторной страницы в одном адаптере не заменяет проверку общего контракта.

## C02 — P1: устаревшие конкуренты участвуют в арбитражных алертах

Это противоречит Q4 («Stale не участвует в лучшей цене и алертах»). Реальных уведомлений проверка не отправляла.

## C03 — P2: при всех Stale API снова рассчитывает сравнение и лидерство

Место: `search_engine.py:699` (`basis = pool or priced`), возврат `price_stats`/`store_comparison`; `web/templates/index.html`, блок Store Comparison Grid около строки 3853.

Когда свежих предложений нет, best_deal корректно становится None, но расчёты переключаются на все устаревшие цены. Воспроизведено на одном четырёхдневном предложении: **all_stale=True, best_deal=None**, одновременно price_stats.min/max/avg=400000 и store_comparison содержит магазин с diff_from_best=0. По коду UI эта карточка получает «🏆 Лидер»: блок сравнения не проверяет all_stale/freshness и не показывает freshnessBadge. Это результат анализа API и шаблона; браузерное воспроизведение в этом аудите не выполнялось.

UI должен показывать «нет актуальных цен для сравнения», без лидера, экономии и фиктивного нуля. Устаревшим строкам не назначать числовую разницу от «лучшей» цены.
