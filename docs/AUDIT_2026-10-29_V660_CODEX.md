## V660-01 [P2] Ожидающий запрос вызывает local после выключения режима

Места: `ai_router.py:203–209`, `ai_service.py:705–713`.

Роутер проверяет режим до обращения к call_local_api. Затем запрос может ждать семафор,
пока другая генерация занимает единственное место. После получения места режим не проверяется
повторно: запрос отправляется к локальной модели даже если за время ожидания нажали «AI выкл»
или gpu_probe выключил её для игры. Смена ai_mode.json не отменяет уже ожидающие запросы.
Ожидавший запрос после выгрузки модели может вновь загрузить её и занять GPU во время игры.
Это отличается от завершения уже начатой генерации: второй HTTP-вызов ещё не был отправлен.

**Независимый сценарий `queued_pause.py`:** настоящий ai_router/call_local_api, временная БД,
loopback-сервер модели и подменённая платная функция. Первый запрос удерживает семафор;
второй подтверждённо ждёт его. Затем записывается `mode=off`, и первый запрос освобождается.
Факт: HTTP-сервер получил **оба** запроса (`first`, `queued`), оба ответа имеют provider=local,
платная функция не вызвана. Проверка ожидаемого ухода второго запроса на fallback падает.
Прямых запросов к настоящей модели/платному сервису не было.

**Рекомендация:** после ожидания, непосредственно перед сетевым вызовом, повторно проверять
текущее разрешение local. Отказ по режиму должен быть отказом до обращения к провайдеру,
с корректным учётом local_paused и переходом к разрешённой платной модели в пределах бюджета.
Не записывать такой отказ как ошибку модели или успешное обращение к ней.

**Приёмка:** запрос в ожидании слота, переключение off, освобождение слота — нового HTTP к local
нет. В auto при доступном бюджете работает разрешённый fallback; при явном local или исчерпанном
платном бюджете — корректный отказ без обхода режима. Уже начатая генерация и отмена ожидания
не теряют семафор. Проверить несколько ожидающих запросов и последующее переключение on.

## V660-02 [P2] Платная досылка после частичного ответа local не учитывается как fallback

Места: `ai_service.py:1261–1272`, `ai_router.py:280–286` (учёт по индексу провайдера).

Часть названий после неудачной локальной нормализации досылается отдельным ai_router.run
с конфигурацией без local. Для этого нового run платный провайдер имеет индекс 0, поэтому
записывается `fallback=False`, хотя платный вызов возник именно вследствие частичного отказа
локальной модели. Информация о связи двух вызовов теряется. Условия политики по доле fallback
и мониторинг эффективности local в таком случае показывают заниженные значения.

**Независимый `partial_fallback_usage.py`:** настоящий путь normalize_product_titles_batch,
маршрутизатор и SQLite-учёт; только функции сетевых провайдеров подменены. Включена локальная
нормализация, auto, два названия: local даёт один корректный ключ и одну пустышку; Gemini успешно
нормализует второе название. Результат содержит оба корректных ключа. В ai_usage — по одному
успешному запросу local/Gemini, но **fallbacks=0 в обеих строках**. Ожидаемый итог 1 — FAIL.

Дефект относится к опционально включённой local-нормализации. По умолчанию переключатель
local_normalize_enabled=False сохраняет решение владельца «нормализация пока на Gemini».
Утверждение о пропущенном fallback не означает отсутствия записи самого платного запроса:
он учитывается, теряется именно признак перехода.

**Рекомендация:** передавать контекст платной досылки в единый учёт, не удваивая запросы,
токены или стоимость. Успех/ошибку fallback отличать от отказа бюджета до реального вызова.

**Приёмка:** частичный ответ local → успешная платная досылка даёт два обращения и один fallback;
полный корректный local — один local и ноль платных/fallback; явный local не досылается;
непроизошедший из-за бюджета платный вызов не получает фиктивных запросов/токенов.

## Подтверждённые исправления и поведение

- **P17ER-03 закрыт:** starting сохраняется до compose up, запись состояния атомарна;
  starting/started запрещают повторную подготовку. Старый независимый late_start_failure.py
  теперь даёт state=starting, replacement_exit=1, runtime_data_preserved=true.
  Установленный на сервере restore_prod.sh совпал с проверенным по SHA-256.
- Штатные тесты восстановления покрывают подготовку/запуск, отказ при живом старом экземпляре,
  защиту чужой базы и отказ замены после попытки запуска. Учёт доставки/проверка удалённой цели
  сохранены; весь пакет вошёл в полный suite.
- Провайдер local идёт первым в auto для разрешённых задач; явный провайдер сохраняет свой выбор.
  normalize по умолчанию исключён из local, opt-in и явный local проверены тестами.
- Исчерпание денежного бюджета исключает платных, но сохраняет local. Локальная не занимает
  резерв платных вызовов, её стоимость 0; local_paused исключён из обращений к провайдерам и ошибок.
- Ошибка HTTP/сети/JSON и отказ валидатора приводят к разрешённому fallback. Один запрос local
  выполняется за раз в процессе; это не глобальная межпроцессная блокировка прода и стенда.
- normalize_ai_canonical_key приводит placeholders к null, отвергает пустышки бренда/модели;
  досылка отправляет только нераспознанные названия. Переключатель отключён по умолчанию;
  качество местных ключей не объявляется принятым (P17-C отдельно).
- Админские endpoints защищены require_admin; конфигурационный API маскирует local_api_key,
  маска при сохранении сохраняет прежний ключ. Валидатор адреса разрешает http(s) без userinfo,
  проверяется имя модели. Это административно задаваемый адрес, а не пользовательский URL.
- ai_switch и gpu_probe используют mode-файл для прода/стенда; штатные тесты проверяют выключение
  при занятой GPU, час ожидания и загрузку модели после простоя. Полная реальная игровая нагрузка
  и конкурирующие запуски cron/кнопок в этом аудите не проверялись.
