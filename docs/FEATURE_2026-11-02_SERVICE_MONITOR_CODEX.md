# Состояние сервиса в новой админке

02.11.2026, Codex по поручению владельца «Дальше». База 512cb33, версия 6.18.4.
Один исполнитель, чужие untracked сохранены. Только стенд, без production/main push.

## Обзор

`/admin#monitoringTool`: магазины, сбор цен, сохранение товаров, локальная модель,
очередь уведомлений и события сервиса. Время снимка явно показано; через 120 секунд
интерфейс предупреждает об устаревании. Обновление выполняется кнопкой, без фонового
опроса модели. Старый `/monitoring` остаётся подробным инструментом и доступен по ссылке.

Магазины используют существующие оценки полноты/свежести `monitoring.shops_overview`.
Смешение healthy/unknown остаётся unknown. Без попыток обхода число товаров неизвестно,
без наблюдений категорий число проблемных категорий неизвестно — нули не подставляются.
Сохранение товаров использует действительные счётчики durable spool и состояние обработчика.
Само наличие pending/processing не объявляется зависанием. Dead letter/rejected показаны отдельно.
Сбор использует существующий `scanning_section` и состояние процесса; изменения scheduler отсутствуют.

Локальная модель: подключение/пауза, свежесть GPU-отметки, сохранённые вызовы за 24 часа.
Учитываются только local/provider_called события; busy/paused/budget-skips не считаются
сетевыми вызовами даже при старой неоднозначной отметке provider_called.
Статистика вызовов не является текущим ping модели. Очередь уведомлений не подтверждает
доставку конкретному человеку, пустая история не даёт healthy. Телеметрия выключена/неизвестна —
отсутствие ошибок не считается подтверждением здоровья. Исторические ошибки не объявляются текущими.

Блоки читаются независимо: исключение одного даёт unavailable/unknown без raw exception,
остальные остаются доступны. Неизвестное значение не превращается в нулевой счётчик.
Настройки, БД, задачи очередей и отправка сообщений этим обзором не меняются.

## Локальный помощник

При открытии/обновлении запускается local-only разбор. Сервер возвращает снимок и рекомендации
вместе: рекомендации относятся к этому снимку, а не к уже обновлённым данным. Запоздавший ответ
после нового обновления отбрасывается; ошибочный GET очищает предыдущие показатели и разбор.

Модель получает только подтверждённые коды проблем с описаниями допустимых действий.
Имена магазинов/людей, ключи, адреса, сырые ошибки, товары и содержимое журналов в prompt не входят.
Принимается только полная перестановка подтверждённых кодов; текст и ссылки берутся из словаря.
Невалидный ответ не создаёт новых проблем/команд. Без ИИ остаются проверенные действия.
Пауза модели и общий слот соблюдаются, платного fallback нет, автоисправлений нет.
RAM cache 120 секунд учитывает коды и фактическое локальное подключение; single-flight busy guard,
HTTP ограничение 6 разборов в минуту. GET не обращается к провайдерам.

## Проверки

Авторские тесты на временных БД/settings: отсутствие наблюдений, ошибка чтения очереди,
независимость блоков, pending не означает stuck, отдельный worker flag, выключенная телеметрия,
фильтрация фактических local calls, пауза/невалидный ответ/кеш/busy, роли и rate limit.
Browser Chrome 390/1366, обе темы: шесть блоков, отказ/восстановление, safe text для внешних имён,
навигация, auto local diagnosis, двойное нажатие, поздний ответ после refresh, отсутствие overflow.
Browser API подставлен. Физический телефон/Safari, основной owner login и независимая приёмка отдельно.
