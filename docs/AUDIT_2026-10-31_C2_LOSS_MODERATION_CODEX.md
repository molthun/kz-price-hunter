## MOD-SEARCH-01 [P2] Ручной поиск обходит суточный предел попыток

`web/server.py:3819–3825`, `admin_matching_search_handler`.

Проверка `web_searches_today() < daily_limit` выполнена единожды перед циклом, но запросы не резервируются через `reserve_web_search`. Сохранение успешной выдачи пишет только кеш, а счётчик считается по `web_search_attempts`. Поэтому ни успешные, ни пустые/неуспешные запросы этого пути не расходуют предел; цикл может вызвать две поисковые попытки даже при одном оставшемся разрешении. Стандартный `verify_pair_cached` уже резервирует каждую попытку атомарно до запроса.

Независимая проверка настоящего локального HTTP endpoint с dev-admin и временной SQLite: limit=1, два разных запроса на пару, два открытия справки, внешняя функция поиска заменена AsyncMock(return_value=None). **4 вызова поиска, учтённых попыток 0**. Реальный SearXNG не вызывался: подтверждён дефект учёта на настоящем API-пути, доступность внешнего сервиса не проверялась.

Критерий закрытия: перед каждым внешним запросом атомарно резервировать попытку; ошибки/пустые ответы расходуют попытку, кеш не расходует, предел 0 запрещает запросы. Проверить один оставшийся слот, повтор и конкуренцию с фоновым обработчиком.

## MOD-SCAN-01 [P2] Решённая пара скрывает другие конфликты той же группы

`database.py:2835–2847`, `find_and_enqueue_conflicting_canonical_keys`.

После первого конфликта устанавливается found_in_group и прекращается проверка группы даже когда `enqueue_disputed_pair(..., force=False)` вернул False для ранее решённой пары. В результате один и тот же конфликт постоянно возвращается без постановки, а другие участники никогда не доходят до очереди.

Воспроизведение: одна группа Galaxy S24 128GB / 256GB / 512GB с сохранёнными полями. Оператор явно разрешил SAME первых двух (допустимое право override самой пары), а решение с третьим участником отсутствует. Два последовательных сканирования оба возвращают **conflicts_found=1, enqueued=0** для уже resolved пары 128/256. Конфликт 128/512 не поставлен ни разу.

Критерий закрытия: не завершать обход группы на уже решённой паре; сохранить человеческий вердикт и продолжить поиск нерешённых конфликтов. Не переоткрывать human SAME автоматически. Регрессии: resolved/pending/skipped первая пара, нерешённый третий участник, повторный запуск без дублей и без голодания оставшихся групп.

## Выборочная слепая перепроверка

До открытия labels.json / strata_sealed.json сохранены выборка и самостоятельные решения по **40** случайным строкам (seed **2026103101**). Аудитор уже знал агрегаты и прежнюю историю C2; слепота относится к меткам и слоям этих 40 пар, не к истории проекта. Все 280 названий были доступны, авторские метки до записи blind-review.json не читались.

- Для **32** пар вынесены определённые решения по явным названиям/артикулам: все совпали с автором. **8** оценены консервативно как uncertain; одна (132, SD/microSD не уточнено) совпала, остальные семь потребовали дополнительной проверки. Это не семь доказанных ошибок.
- После источников строка **0** подтверждена как same: официальный [OSCAL Pad 9](https://www.oscal.hk/pad9) указывает физические 4GB / 128GB и 4G; отсутствие LTE в одном названии здесь не означает другую модификацию.
- Для **115** подтверждено different: официальные спецификации [KF432C16BB12AK2/32](https://www.kingston.com/datasheets/KF432C16BB12AK2_32.pdf) и [KF432C16BB2AK2/32](https://www.kingston.com/datasheets/KF432C16BB2AK2_32.pdf) действительно различают 16-18-18 / 16-20-20 и 2Rx8 / 1Rx8.
- **163**: в названиях явно V9/V8; different согласуется с заявленной политикой различать ревизии, характеристики каждой ревизии не сертифицировались.
- **22, 113, 151, 171** оставлены для адресного подтверждения: суффикс модели Philips; исполнение NOMAD с/без радиатора; Doogee с годом только в одном названии; комплект Jabra WLC. Авторские ссылки для 113/171 ведут лишь на корни сайтов, этого недостаточно для воспроизводимого подтверждения конкретного исполнения. Официальная [Doogee Tab A9](https://www.doogee.com/products/tab-a9) подтверждает 3/64GB, но не доказывает тождество исторических поколений. [Jabra Support](https://www.jabra.com/supportpages/jabra-evolve2-65-flex) показывает отдельные варианты с беспроводной зарядкой и без; точное соответствие обоих артикулов первичным источником здесь не установлено. Для Philips конкретная страница была недоступна.

Четыре оставшихся вопроса — ограничение выборочной приёмки доказательств, не доказанные неверные метки. Остальные 240 пар сплошь не перепроверены. Метки аудитором не менялись. Для окончательного принятия разметки сохранить прямые карточки/даташиты с существенными характеристиками либо оставить неподтверждённые случаи uncertain и пересчитать отчёт.
