## 4. Разбор потерь по фактическим ключам C3

### 4.1. `dropped_mixed` — 522 пары: поля не получены, а не «нет бренда»

- Во всех 522 парах одна сторона осталась с прежним ключом. Причины: `missing_fields_one_side` 521, `legacy_with_fields` 1 (SANDISK Blue 500GB), подтверждённых `no_identity` **0**.
- Прежний текст о «товарах без бренда и идентичности» отозван. Среди потерянных пар есть явно брендированные AOC 27G42E и Kingston KC600.
- Эти потери обоснованными не считаются: свежая выборка даёт 16 настоящих совпадений из 60.

### 4.2. Незавершённый остаток прохода

- Проход по 1 107 названиям: 409 получили k2, 16 подтверждённых `no_identity`, **682 не завершены** (480 failed + 202 missing); 24 ошибки API из 56 вызовов. Полей для всех 1 107 не получено, строка раздела 1 об извлечении относится только к 409.
- В копии 682 legacy-названия: у 472 нет строки полей, у 210 есть; ни одно не помечено `unbranded=true`.
- **Остаток перечислен полностью:** все 682 названия в `docs/audit_evidence/2026-10-31-c3a/residue_titles.json`; 186 входят в потерянные пары, 496 нет. Выгрузка сделана с разрешения владельца только чтением `prices_k2_c3.db` (`mode=ro`, `query_only=ON`, сценарий `read_residue.py`); числа 682/472/210 и отсутствие `unbranded=true` совпали с аудитом. Какие из них failed, а какие missing, по названиям не определить: отчёт прохода хранит только числа.
- Все 210 строк с полями содержат бренд, но ключа k2 не получили (пример: `27" ABIX черный`, `SANDISK Blue 500GB`).

### 4.3. `dropped_both_k2` — 444 пары

Причины: `identity_differs_other` 209, `variant_conflict` 114, `identity_differs_shared_code` 80, `revision_differs` 23, `variant_one_side` 18.

- **Ryzen 5 7600X:** прежний разбор отозван. В C3 обе BOX-строки уже имеют `k2:amd:ryzen57600x.box`, новая правка не нужна. Единственные потерянные пары 7600X здесь — BOX против OEM (`k2:amd:ryzen57600x.box` и `k2:amd:ryzen57600x`), это намеренное разделение по решению владельца.
- **XTREON XT24N1:** разделение подтверждено аудитом. `k2:xtreon:xt24n1:23.8in` против `k2:xtreon:xt24n1`: во втором названии диагональ без знака дюйма.

## 5. Выводы по критериям C2

1. **Настоящих совпадений не меньше 95 % от прежнего кэша: выполнен.** Нижняя граница отношения 1,734, при других решениях об упаковке не ниже 1,711. Это рост за счёт новых пар, а не сохранение прежних.
2. **Ложных склеек не больше, чем у прежнего кэша: точечно выполнен, границами НЕ доказан.** Точечно 157 против 622 (0,252), но верхняя граница 1,444 > 1. Заявление «k2 гарантированно чище» отозвано. Разбор открытых пар этого не решает (раздел 3.6), нужна расширенная независимая выборка слоёв `added` и `retained`; менять ради этого правила или способ счёта нельзя.
3. **Прямая сохраняемость: 73,9 % (нижняя граница 61,4 %).** Отдельным критерием передачи не является и показывается для сведения. Главная устранимая часть потерь — незавершённые поля из раздела 4.

**Итог: заявить C2 выполненным нельзя.** Данные указывают на заметное улучшение, но критерий по склейкам не подтверждён. Рабочая миграция и включение k2 остаются только по решению владельца. Оценка требует повторной независимой приёмки Codex.
