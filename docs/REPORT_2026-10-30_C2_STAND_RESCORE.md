## 3. Качество: новая разметка и оценка обеих сторон

**Почему прежний набор не годится.** 210 пар (291 уникальное название, а не 420) собраны из исхода самого прогона: положительные почти только из новых пар, отрицательные из потерянных. Метка «разные» часто опиралась на разные поля модели. При пересмотре вслепую из 105 отрицательных меток подтвердились только 16, 77 оказались одним товаром, 12 не решить по названию. Из 105 положительных 79 подтвердились, 25 различаются поставкой (OEM/BOX, теперь разные товары), 1 неясна. Набор переразмечен (`scripts/k2_verified_pairs.json`, версия 3) и оставлен для регрессий. Качество каталога по нему не оценивается.

**Как оценено теперь.** `scripts/k2_labeled_sample.json`: случайная выборка по слоям (seed 20261030) плюс прежние пары, всего 459 пар и 638 названий. Разметка по названиям вслепую: без ключей, полей и слоя, порядок перемешан. Метки: same 326, different 69, packaging 40 (OEM/BOX, разные товары по решению владельца), uncertain 24 (не считается). `scripts/c2_quality_report.py` считает прежний кэш и k2 одной формулой. Итог и реестр: `docs/audit_evidence/2026-10-30-c2-labels/`.

**Решение владельца 30.10.2026: OEM/Tray и BOX — разные товары.** Правила k2 их сейчас объединяют, поэтому такие пары считаются ложными склейками.

Доля настоящих совпадений в слоях (95 % Уилсон):

| Сохранились (retained) | 899 | 45 из 52 | 87 % | 75–93 % |
| Потеряны, одна сторона без полей | 660 | 27 из 57 | 47 % | 35–60 % |

**Ложные склейки k2: 22 из 95 новых пар в выборке (23 %) и 7 из 52 сохранённых.** Из них 15 — OEM/BOX, остальные 14 — другие классы: длина кабеля (PP12 0,5 м и 1 м, 3 м и 15 м), размер часов (Fenix 8 43, 47, 51 мм), адаптер и версия гарнитуры (Evolve2 Link380a и Link380c, MS и UC, 65 и 65 Flex), длина сетевого фильтра (5 м и 1,8 м), Wi-Fi у платы (B850M-X), DDR4 и DDR5 (Netac Basic), приставка и геймпад (PlayStation 5). Прежний кэш тоже объединял OEM и BOX, в сохранённых парах они остаются.

**Ограничения.**
- Размечал один исполнитель (Claude), он же автор части правил. Источник производителя есть только у пяти пар из аудита, остальное — чтение названий.

- Интервалы отношений — грубые (границы слоёв вместе).

## 5. Реестр потерянных и новых пар

Полный реестр: `docs/audit_evidence/2026-10-30-c2-labels/registry.json`. У каждой пары ровно одна причина, суммы сверяются с 1071 и 2695 при каждом запуске. Причина описывает устройство ключей, а не то, правильно ли разделение: долю настоящих совпадений даёт раздел 3.

**Потеряно 1071:**

| Причина | Пар |
|---|---:|
| Одна сторона без полей: старый ключ против k2 | **660** |
| Разные варианты в ключах | 133 |
| Разная идентичность, общего кода в названиях нет | 181 |
| Разная идентичность при общем коде в названиях | 56 |
| Разная ревизия | 23 |
| Вариант только с одной стороны | 18 |
| Хотя бы одна сторона с пустым ключом (`no_identity`) | **0** |

Прежняя «категория 2» (≈660 пар безымянных товаров) была ошибочной: ни одна потеря не связана с `no_identity`, у всех 660 просто нет полей с одной стороны. Это потеря от незавершённого перехода, а не защита от склеек: почти половина этих пар — настоящие совпадения (раздел 3). Они восстанавливаются, если получить поля для 767 названий без полей: обычный проход миграции запрашивает их сам, этот прогон шёл с `--rescore-only`.

Названия: 18 461 k2, 1104 со старым ключом (767 без полей и 337 неполных), 568 без ключа, всего 20 133.

**Различие двух k2-ключей — чаще потеря, чем исправление:** в выборке 78 % таких пар один товар. Примеры настоящих потерь:
- модель записывает в поле модели артикул, серию или маркетинг: `k2:asrock:a520m` и `k2:asrock:a520mhvs`, `k2:dreame:65s100` и `k2:dreame:aura65s100`, `k2:razer:barracuda` и `k2:razer:barracudaquartz`;
- в вариант попадает лишнее: `k2:tecno:spark50:256gb+6.78in+8gb` и `k2:tecno:spark50:256gb+8gb`;
- длина и цвет в артикуле: `k2:cablexpert:pp123mb` и `k2:cablexpert:pp12`;
- XTREON XT24N1: `k2:xtreon:xt24n1:23.8in` и `k2:xtreon:xt24n1`, в названии `23.8` без знака дюйма.

AMD Ryzen 5 7600X: `build_key` по этим полям строит `k2:amd:ryzen57600x` у обеих сторон, а в копии у первой стороны `k2:amd:ryzen5`. Причина не установлена: нужна трассировка на копии, она не выполнялась.

## 6. Выводы

1. **Копия пересобрана, строки сохранены.** Codex подтвердил снимок, прогон и сохранность products, offers и истории цен.
2. **Критерий C2 по склейкам не выполнен.** Настоящих совпадений примерно вдвое больше, но и ложных склеек оценочно в 1,33 раза больше, их 23 % среди новых пар. Около 45 % настоящих совпадений прежнего кэша потеряно.
3. **Рост числа пар на 82,4 % сам по себе качество не показывает.**
4. **К рабочей миграции и включению локальной нормализации k2 не готов.**

Что нужно дальше:
- второй независимый разметчик или проверка выборки Codex;
- случайная выборка всех 899 сохранённых пар: она требует чтения копии на стенде;
- отдельная задача на правила ключа (поставка OEM/BOX, длина кабеля, размер часов, адаптер, тип памяти, тип товара, поля модели), затем запрос полей для 767 названий и повтор этой оценки на тех же парах.

## 7. Правила ключа после разбора (Claude, 30.10.2026, по поручению владельца)

Изменён `product_key.py`:
- поставка процессора: BOX, WOF и «с кулером» отделены от OEM, Tray и названий без поставки (`.box`), решение владельца;
- длина кабелей, удлинителей и сетевых фильтров: вариант `3m`; длина и цвет убраны из кода модели (`PP12-3M/B` → `pp12`);
- диаметр часов: вариант `47mm`;
- память определяется полным кодом производителя, а не линейкой (Fury Beast); без кода различается DDR4 и DDR5;
- Wi-Fi у материнских плат (`.wifi`), адаптер, платформа и Flex у Jabra (`.link380a`, `.ms`, `.flex`), аксессуар к товару (`.acc`);
- маркетинг телевизоров (QLED, MiniLED, UHD, Smart и другие) не входит в модель;
- диагональ экрана меньше 10 дюймов и пропускная способность `6Gb/s` не считаются вариантами.

Разные метки запрещают связь по артикулу и объединение по вердикту поиска. Связь при общем коде в поле артикула и разной записи модели не менялась: это путь через проверку спорных пар (P17C-01), поэтому Razer Barracuda и Barracuda Quartz по-прежнему разделены до вердикта.

**Оценка на отложенной выборке** (seed 20261031: 90 новых и 60 потерянных k2-пар, не входили в первую разметку). Ключи пересчитаны из сохранённых полей, связь по артикулу только внутри пары:

| Слой | Настоящие вместе | Ложные вместе |
|---|---|---|
| Новые пары, копия → правила | 70 из 70 → **69** | 18 из 18 → **3** |
| Потерянные k2-пары, копия → правила | 0 из 42 → **21** | 0 из 15 → **0** |
| Первая выборка, новые пары (на ней подбирались правила) | 73 из 73 → 71 | 22 из 22 → 0 |
| Сохранённые, 52 доступные | 45 из 45 → 45 | 7 из 7 → 1 |
| Потерянные без полей | 0 из 27 → 0 | 0 из 30 → 0 |

Оценка на каталог по этим долям: настоящих ≈3043, ложных ≈109. Прежний кэш: ≈1410 и ≈560. Из 2695 новых пар вместе остаются 2143, из 411 потерянных k2-пар вернулись 139.

**Это ещё не приёмка C2:**
- копия не пересобрана: считались только пары прежних слоёв и связь внутри пары, а новые склейки в группах каталога здесь не видны. Поэтому ≈109 — нижняя оценка ложных склеек;
- отложенная выборка задета: после её разметки я увидел оставшиеся ложные склейки и исправил ошибку, из-за которой связь по артикулу снимала метки. Правка общая, но честная цифра будет только на новой выборке после пересборки;
- 660 потерь без полей не восстановлены: нужно запросить поля для 767 названий у модели;
- остаются ложные склейки: Mono и Stereo у Jabra, EarPods USB-C и Lightning, i7-10700 и 10700K (по извлечённым полям);
- разметка по-прежнему один исполнитель;
- XTREON XT24N1 и Ryzen 5 7600X не разобраны.

**Следующий шаг после аудита правил:** свежая копия `snapshot_before_k2.db` с полями, `--run-id c3-rules --rescore-only --check-pairs`, затем обычный проход для 767 названий без полей, затем новая случайная выборка всех слоёв, включая 899 сохранённых, и второй проверяющий.
