## 3. Оценка качества каталога (`scripts/c2_quality_report.py`)

> Разделы 3–5 переписаны Claude 31.10.2026 по аудиту C3A-01–03 (`docs/AUDIT_2026-10-31_C3_QUALITY_CODEX.md`). Свидетельства: `docs/audit_evidence/2026-10-31-c3a/`.

### 3.1. Как считается

- **Известная часть слоя** (537 пар, размеченных до отбора; в новый отбор они попасть не могли) считается как есть, по своим меткам.
- **Свежая выборка** распространяется только на остаток слоя (899/476/284/2054).
- **uncertain не распределяется:** в точечной оценке это отдельная строка, а в границах считается против k2.
- **Границы:** совместный интервал Уилсона с поправкой Бонферрони на 8 интервалов (z = 2,734); границы отношений берут худшее сочетание. Сохранившиеся пары входят в обе стороны с противоположными краями, поэтому границы осторожнее заявленных 95 %.

### 3.2. Пересмотр меток

Журнал и источники: `docs/audit_evidence/2026-10-31-c3a/label_changes.json`, сценарий: `apply_label_review.py`. Всего 48 изменений:

- две ошибки из аудита исправлены на `same`: HyperX DG0R2AA/A59Z0AA и Kaira X Pulse Red/White;
- 13 прежних `same: null` снова `uncertain`; ошибочный перенос в `2026-10-30-c3/build_labeled_dataset.py:355` заменён этим сценарием;

- 2 пары из известной части исправлены на `different`: Spark 50 6 ГБ/8 ГБ, Kingston KF560C36/KF560C30.

**Ограничение:** пересмотр по названиям сделал исполнитель, уже знавший прежние итоги, поэтому он не независимый. Сплошной проверки у производителей не было; источниками подтверждены только пары, перечисленные в журнале.

## 4. Разбор потерь по фактическим ключам C3

### 4.1. `dropped_mixed` — 522 пары: поля не получены, а не «нет бренда»

- Во всех 522 парах одна сторона осталась с прежним ключом. Причины: `missing_fields_one_side` 521, `legacy_with_fields` 1 (SANDISK Blue 500GB), подтверждённых `no_identity` **0**.
- Прежний текст о «товарах без бренда и идентичности» отозван. Среди потерянных пар есть явно брендированные AOC 27G42E и Kingston KC600.
- Эти потери обоснованными не считаются: свежая выборка даёт 16 настоящих совпадений из 60.

### 4.2. Незавершённый остаток прохода

- Проход по 1 107 названиям: 409 получили k2, 16 подтверждённых `no_identity`, **682 не завершены** (480 failed + 202 missing); 24 ошибки API из 56 вызовов. Полей для всех 1 107 не получено, строка раздела 1 об извлечении относится только к 409.
- В копии 682 legacy-названия: у 472 нет строки полей, у 210 есть; ни одно не помечено `unbranded=true`.
- **Перечислена только часть:** 186 названий из потерянных пар — `docs/audit_evidence/2026-10-31-c3a/residue_titles.json` (185 без полей, 1 с полями). Остальные 496 в выгрузке отсутствуют. Для полного списка нужно чтение копии на стенде, поэтому требование C3A-03 перечислить остаток закрыто не полностью: чтение возможно только с разрешения владельца.

### 4.3. `dropped_both_k2` — 444 пары

Причины: `identity_differs_other` 209, `variant_conflict` 114, `identity_differs_shared_code` 80, `revision_differs` 23, `variant_one_side` 18.

- **Ryzen 5 7600X:** прежний разбор отозван. В C3 обе BOX-строки уже имеют `k2:amd:ryzen57600x.box`, новая правка не нужна. Единственные потерянные пары 7600X здесь — BOX против OEM (`k2:amd:ryzen57600x.box` и `k2:amd:ryzen57600x`), это намеренное разделение по решению владельца.
- **XTREON XT24N1:** разделение подтверждено аудитом. `k2:xtreon:xt24n1:23.8in` против `k2:xtreon:xt24n1`: во втором названии диагональ без знака дюйма.

## 5. Выводы по критериям C2

1. **Настоящих совпадений не меньше 95 % от прежнего кэша: выполнен.** Нижняя граница отношения 1,716 при всех решениях об упаковке не ниже 1,695. Это рост за счёт новых пар, а не сохранение прежних.
2. **Ложных склеек не больше, чем у прежнего кэша: точечно выполнен, границами НЕ доказан.** Точечно 134 против 622 (0,216), но верхняя граница 1,503 > 1. Заявление «k2 гарантированно чище» отозвано. Чтобы сузить границу, нужно разобрать открытые пары `added` или увеличить выборку; менять ради этого правила или способ счёта нельзя.
3. **Прямая сохраняемость: 73,9 % (нижняя граница 61,4 %).** Отдельным критерием передачи не является и показывается для сведения. Главная устранимая часть потерь — незавершённые поля из раздела 4.

**Итог: заявить C2 выполненным нельзя.** Данные указывают на заметное улучшение, но критерий по склейкам не подтверждён. Рабочая миграция и включение k2 остаются только по решению владельца. Оценка требует повторной независимой приёмки Codex.
