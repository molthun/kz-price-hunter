## OA-01 [P2] Для второго предложения Jabra выведен отсутствующий артикул

Место: `docs/audit_evidence/2026-10-31-c3a/apply_open_added_review.py`, запись CHANGES для пары:

- `Гарнитура JABRA Evolve2 50, USB C/A, MS Stereo (25089-999-799)`;
- `Наушники Jabra Evolve2 50 USB-C MS Stereo черный`.

Uncertain заменено на different на основании предполагаемого второго артикула **25089-999-899**. Но ни в названии второго предложения, ни в его сохранённом поле sku этого артикула нет. Указание USB-C не доказывает отсутствие адаптера USB-A. Сравнение двух существующих артикулов само по себе не устанавливает, какой из них продаётся во втором предложении. Производитель действительно перечисляет разные USB-C и USB-C/A варианты, однако связать конкретное предложение с одним из них всё равно требуется отдельно. См. [спецификацию Jabra](https://www.jabra.com/_/media/Jabra_VXi_Product-Documentation/Jabra-Evolve2-50/Technical-specifications/RevB/EN-JabraEvolve2-50-Tech_spec_v17022025.pdf).

Для проверки только чтением найден исходный URL второго товара в копии C3: **Forte Market**, [карточка предложения](https://market.forte.kz/items/naushniki-jabra-evolve2-50-usb-c-ms-stereo-chernyj-1690455). Прямой HTTP GET вернул 200; в данных страницы `nomenclatures_data` присутствует наименование **Jabra Evolve2 50 MS Stereo USB-C/A, 25089-999-799**. Это тот же артикул, что у первого товара, и дополнительное свидетельство против автоматического вывода …899 из короткого заголовка USB-C.

Текущая карточка не считается доказательством неизменности ассортимента на дату старого снимка. Поэтому безопасный итог для исторического набора — **uncertain до подтверждения конкретного артикула на срезе**, либо same при достаточном подтверждении. Уверенная different представленными данными не обоснована. Содержимое журнала и исходные метки аудитором не изменялись.

Влияние мало и не меняет отрицательного вывода о C2: возврат только этой known-пары в uncertain даёт ложных **157 вместо 158**, открытых **140 вместо 139**; верхняя граница остаётся **1,444**. Это проверено пересчётом в памяти (`jabra-sensitivity.json`). Замечание касается достоверности разметки, а не нового дефекта правил ключа.

Критерий закрытия: убрать неподтверждённый …899 и исправить метку/причину в журнале и наборе либо предъявить проверяемое свидетельство конкретного артикула предложения на срезе. Пересчитать quality и sensitivity, затем повторно проверить изменённую запись. Не менять правило ключа для достижения порога.
