## Остаток C2R-03 [P1]: Core Ultra BOX без полей переносится в OEM-группу

Место: `product_key.py:526` (проверка BOX в `_title_marks`), используемый шаблон `_CHIP_IN_TITLE_RE` на строках 260–261.

Новый профиль участника без полей получает BOX только при совпадении названия с `_CHIP_IN_TITLE_RE`. Этот шаблон распознаёт `core i<цифра>`, но не `Core Ultra`. При этом построение собственного ключа по полям поддерживает такую модель через `_CPU_RE`. Поэтому один и тот же явный BOX виден только при наличии полей:

```text
Название: Intel Core Ultra 7 265K BOX
_title_marks: frozenset()
build_key при наличии полей: k2:intel:coreultra7265k.box
```

Независимое воспроизведение создаёт временную SQLite с двумя OEM-названиями одной модели и третьим BOX-названием без полей в сохранённой группе второго. Только внешний ответ верификатора подменён на корректный для двух OEM `same`. Реальные очередь, проверка группы, перенос кеша и V2-предложений выполняются штатным кодом.

Результат worker — `resolved`, все три названия получили один OEM-ключ `intel:coreultra7265k:oem`, все три предложения — один `product_id`. Ожидание — отказ от переноса всей группы (`unresolved`) с сохранением исходных связей. Это ложное объединение, а не только объявленный в передаче консервативный отказ в объединении.
