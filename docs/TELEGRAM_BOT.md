# Telegram-бот KZ Price Hunter: возможности, виджеты и очередь развития

Живой документ. Обновляется вместе с каждой задачей по боту: что бот умеет, какие возможности Bot API
использует, что проверено и что стоит в очереди. Очередь здесь — детализация этапа «Поколение TG» из
[DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md), а не отдельная дорожная карта; порядок и запуск задач решает владелец.

Источники: [Bot API](https://core.telegram.org/bots/api), [журнал изменений](https://core.telegram.org/bots/api-changelog),
[обзор возможностей](https://core.telegram.org/bots/features), [гайд по виджетам](https://core.telegram.org/bots/widgets),
[FAQ](https://core.telegram.org/bots/faq). Сверено 10.11.2026, актуальная версия — Bot API 10.4 (09.11.2026).

## 1. Что бот делает сейчас

| Сценарий | Где в коде | Методы Bot API |
|---|---|---|
| Приём сообщений, long polling, очередь по чатам | `telegram_bot.py` (`run_telegram_bot_task`, `TelegramDispatcher`) | `getUpdates` |
| `/start`, `/help`, `/new`, `/status` | `telegram_bot.py` | `sendMessage` (HTML); глубокие ссылки `start=<payload>` (TG-09) |
| Меню команд и кнопка меню (под выключателем) | `telegram_bot.py` (`setup_bot_menu`) | `setMyCommands`, `setChatMenuButton` |
| `/search` — лучшие цены | `telegram_bot.py` (`handle_search_command`) | `sendMessage`; под выключателем — `sendWidget` (TGW-01) |
| AI-консультант (`/ai` и любой текст), память 30 минут | `telegram_bot.py` (`handle_ai_consultant_message`) | `sendChatAction`, `sendMessage`; под выключателем — `sendMessageDraft` (TG-02) |
| `/watches` и кнопка «Не следить» | `telegram_bot.py` | `sendMessage`, `answerCallbackQuery`; под выключателем — `sendWidget` (TG-07) |
| Оповещения о ценовых находках | `notifier.py` (`send_telegram_alert`) | `sendPhoto` → при отказе фото `sendMessage` |
| Учёт блокировки бота | `telegram_bot.py` (`handle_my_chat_member`), `notifier.py` (`note_delivery_result`) | обновление `my_chat_member` |
| Погашение устаревших находок (под выключателем) | `notifier.py` (`mark_stale_alerts`) | `editMessageCaption`, `editMessageText` |
| Сообщения и сводки по наблюдениям, суточная сводка | `notifier.py` | `sendMessage` |
| Служебные проверки | `telegram_admin.py`, `auth.py` | `getMe`, вход через Telegram Login |

Общее: только личные чаты; запросы к Bot API — напрямую по HTTP (`aiohttp` в боте, `requests` в рассылке), без
библиотек. Ответ 429 с `retry_after` рассылка уже учитывает (`classify_telegram_response`).

## 2. Пилот TGW-01: карточка `/search` виджетом

**Статус:** работает на стенде; владелец открыл карточку в настоящем Telegram на iPhone 10.11.2026 — карточка,
цены и кнопки отображаются. Сортировки, «Следить» и «Обновить» владельцем пока не подтверждены.

Что получает пользователь: одно сообщение-карточку вместо текста с пятью кнопками — до 8 магазинов, от каждого
одно самое дешёвое предложение (решение владельца 10.11.2026: расцветки одного товара не занимают место других
магазинов), сортировка
«дешевле / скидка больше / только со скидкой» прямо в карточке без обращения к боту, строка открывает магазин,
кнопки «Следить за ценой» и «Обновить». Над карточкой — одна строка подписи: запрос и лучшая цена; списка цен
в подписи нет, чтобы не дублировать карточку (замечание владельца после проверки на стенде).

### Включение

Переменная окружения `TELEGRAM_SEARCH_WIDGET`: `off` (по умолчанию) | `admins` (только `ADMIN_TELEGRAM_IDS`) | `all`.
Читается при каждом `/search`; после изменения `.env` достаточно пересоздать контейнер. При любом отказе
(`sendWidget` отклонён, карточка не помещается, предложений нет) бот отправляет прежнее текстовое сообщение.

### Как устроено

- `telegram_widgets.py` — сборка HTML, подписи и `chat_data`; в сеть и базу не ходит.
- `telegram_bot.py` — `send_tg_widget`, `answer_widget_query`, `edit_tg_widget_data`, `handle_widget_query`.
- Запросы карточки (`widget_query`): `w` — создать наблюдение вида «поиск» по запросу карточки (условие
  «любое снижение»), `r` — перечитать цены и записать их в `chat_data`.
- «Обновить» перечитывает цену того же товара, что показан в строке. Если у магазина самым дешёвым стал другой
  товар, строка этого не покажет — нужен новый `/search`.
- Память карточек — в процессе (`_widget_cards`, 6 часов, до 2000 карточек). После перезапуска карточка
  отвечает «повторите /search»; текст запроса в базу не пишется.
- Защита: тот же контур, что у сообщений (личный чат самого пользователя, блокировка), отдельный лимит
  20 нажатий в минуту, «Обновить» не чаще раза в 30 секунд на карточку, «Следить» — только для тех, кто уже
  входил на сайт (у кого есть запись пользователя и настройки уведомлений).

### Пределы виджетов, под которые сделана карточка

| Предел | Значение | Что из этого следует |
|---|---|---|
| HTML | 32768 байт и 4096 байт после zlib-9 | Сборщик убирает предложения с конца, пока не уложится в 3900 |
| Сеть и внешние файлы | нет; картинки только `data:` (PNG/JPEG/GIF/WebP) или встроенный SVG | Фото товара в карточке нет |
| Высота | до 600 px, прокрутки нет, лишнее обрезается | Строка предложения — всегда две линии (скидка под ценой справа); карточка сама убирает строки с конца, пока не уложится в 560 px, чтобы кнопки внизу были видны при любом размере шрифта |
| Элементы управления | только `button`; полей ввода нет | Фильтры — кнопками |
| `chat_data` / `public_data` | по 1024 байта | В `chat_data` только цены по индексам и время |
| Запрос боту | 1–64 байта, ответ до 1024 байт, 15 секунд | Действия кодируются одной буквой |
| Запросы пользователя | 5 за 5 секунд на пользователя и бота | — |
| Ссылки | только `https`, до 256 символов, открытие с подтверждением | Длинные и `http` ссылки становятся строкой без перехода |
| Где работают | продакшен Telegram: только личные чаты; пересылка и копирование запрещены | Карточкой нельзя поделиться |
| Изменение | `editMessageWidgetData` тихое, но считается отправленным сообщением | Обновление — по нажатию, не по расписанию |
| Старые приложения | видят «неподдерживаемое вложение» и подпись | Подпись содержит запрос и лучшую цену; полный список — по кнопке «Все результаты на сайте» |

`widget_query` приходит в `getUpdates` по умолчанию; если когда-нибудь будет задан `allowed_updates`, в него
нужно добавить `widget_query` и `shared_widget_query`.

### Не проверено

- Поведение в настоящем приложении Telegram: движок виджетов — QuickJS в песочнице, не браузер. Локально
  карточка проверена только в Chromium (сортировка, обновление цен, ответы бота, отсутствие ошибок скрипта).
- Минимальная версия приложения с поддержкой виджетов в документации не названа.
- Тексты разделов `editMessageWidgetData` / `editSharedWidgetData` в справочнике прочитаны в пересказе.

## 2а. TG-05: меню команд и кнопка меню

**Статус:** реализовано локально, тесты пройдены; на стенде — см. карточку в [AGENT_HANDOFF.md](AGENT_HANDOFF.md).

Переменная `TELEGRAM_MENU_BUTTON`, применяется при запуске бота (`setup_bot_menu` в `telegram_bot.py`):

| Значение | Что делает бот при запуске |
|---|---|
| `off` (по умолчанию) | Ничего: меню остаётся таким, каким настроено в BotFather |
| `commands` | `setMyCommands` — список команд по «/»; кнопка меню — стандартная «Меню» |

**Решение владельца (10.11.2026):** кнопка меню — быстрые команды бота, режим `commands`; раздел «Скидки» с кнопки
убран. Режим `webapp` остаётся в коде как возможность.

Main App (кнопка «Открыть» в профиле бота, включён в BotFather) уже открывает главную сайта, поэтому в режиме
`webapp` кнопка меню
ведёт в отдельный раздел: `TELEGRAM_MENU_BUTTON_PATH` (по умолчанию `/deals`) и подпись `TELEGRAM_MENU_BUTTON_TEXT`
(по умолчанию «Скидки», до 16 символов). Разделы с прямым адресом: `/deals`, `/search`, `/favorites`, `/profile`.
Путь проверяется: только `/` и латиница, цифры, `_`, `-`; иное заменяется умолчанием.

Сайт в Mini App входит сам: страница передаёт `initData` в `/api/auth/telegram-webapp`, подпись проверяет
`verify_telegram_webapp_data` в `auth.py` — это уже было в проекте. Кнопка `webapp` ставится только для адреса
`https://`; иначе остаётся стандартная. Настройка меню через API и через BotFather (Mini Apps → Menu Button) —
одно и то же: последний записавший определяет результат, поэтому при `webapp` бот при каждом запуске вернёт
свою кнопку. Возврат к прежнему виду: `TELEGRAM_MENU_BUTTON=commands` и перезапуск.

Не сделано: локализация команд на казахский, описание бота (`setMyDescription`).

## 2б. TG-02: ход работы консультанта черновиком

**Статус:** реализовано, тесты пройдены; состояние стенда — в [AGENT_HANDOFF.md](AGENT_HANDOFF.md).

Переменная `TELEGRAM_AI_DRAFTS`: `off` (по умолчанию) | `admins` | `all`.

Что видит пользователь вместо «печатает…»: сразу заглушка «Думаю…» (пустой черновик), затем «Ищу подходящие
товары…», затем «Нашёл предложений: N. Сравниваю цены…», и кнопка «Стоп». Готовый ответ приходит обычным
сообщением — черновик при этом исчезает сам.

Как устроено (`telegram_bot.py`: `send_tg_draft`, `DraftProgress`, `_consult`, `handle_generation_stopped`):

- Один черновик на вопрос (`draft_id` не меняется, поэтому смена текста анимируется).
- Черновик живёт около 30 секунд, поэтому текущий текст повторяется каждые 12 секунд, пока модель думает.
- Этапы сообщает сам консультант: необязательный параметр `on_stage` у `ai_service.ask_ai_consultant`.
- «Стоп» приходит обновлением `stopped_message_generation` (по умолчанию доставляется). Оно обрабатывается мимо
  очереди чата, отменяет обращение к модели, бот отвечает «Остановлено», вопрос в память диалога не попадает.
- Если Telegram черновик не принял, бот работает как раньше — со статусом «печатает…».

**Почему не текст ответа по словам.** Консультант получает от модели один строгий JSON (ответ, идентификаторы
товаров, подсказки) через AI-роутер с бюджетами и проверкой формы — по частям такой ответ показывать нельзя.
Настоящий поток (TG-02б) требует потокового вызова у провайдеров, изменений в `ai_router.run` и другого формата
ответа; это затрагивает этап P08 и делается отдельным решением владельца.

Не проверено: продлевает ли повтор черновика его 30 секунд (в документации не сказано — принято, что да);
ограничения частоты для черновиков в документации не названы.

## 2в. TG-04: учёт блокировки бота

**Статус:** реализовано, тесты пройдены; состояние стенда — в [AGENT_HANDOFF.md](AGENT_HANDOFF.md).

Раньше о блокировке бот узнавал только по ошибке очередной отправки и продолжал пытаться с каждым новым
уведомлением. Теперь у пользователя есть отметка `users.bot_blocked_at` (время первой блокировки, `NULL` — нет).

| Событие | Что происходит |
|---|---|
| Обновление `my_chat_member` со статусом `kicked` в личном чате | Отметка ставится |
| Telegram ответил 403 на отправку уведомления | Отметка ставится (бот заблокирован, чат не начат или аккаунт удалён) |
| Обновление `my_chat_member` со статусом `member` | Отметка снимается |
| Человек написал боту любое сообщение | Отметка снимается — писать заблокированному боту нельзя |

Пока отметка стоит: новые находки этому человеку в очередь не ставятся (`get_notification_recipients`), уже
стоящие в очереди — отменяются без обращения к Telegram (находки, наблюдения, суточная сводка). Вход на сайт,
наблюдения и настройки не затрагиваются: это не `is_blocked`, который ставит администратор.

Где видно: поле `bot_blocked` в `GET /api/admin/users`, поле `bot_blocked_at` в выгрузке «Мои данные».
Выключатель: `TELEGRAM_BLOCK_TRACKING=off` (по умолчанию включено) — отметки не ставятся, не снимаются и не
учитываются. Колонка добавляется аддитивно при запуске (`_add_column`), версия схемы не меняется.

Не сделано: подсказка на сайте «вы заблокировали бота, уведомления не приходят»; значок в списке пользователей
в интерфейсе администратора (поле в API уже есть).

## 2г. Кнопки на сайт открывают Mini App

Замечание владельца (10.11.2026): при переходе из бота на сайт вход не происходил. Причина: обычная `url`-кнопка
открывает встроенный браузер Telegram, а данные для входа (`initData`) сайт получает только как Mini App.

`notifier.site_button(text, url)` теперь делает для адресов нашего сайта по `https` кнопку `web_app`; сайт
открывается внутри Telegram и входит сам. Ссылки на магазины остались обычными. Затронуты кнопки: «Открыть дашборд
цен», «Перейти в каталог», «Все наблюдения на сайте», «Все результаты на сайте», «Смотреть на сайте», «Дашборд
цен», «Мои наблюдения», «Центр мониторинга». `TELEGRAM_SITE_BUTTONS=url` возвращает прежние ссылки.
Попутно исправлено: запрос в ссылке «Все результаты на сайте» теперь кодируется для URL.

Ограничение: `web_app`-кнопки работают только в личных чатах — бот других не обслуживает.

## 2д. TG-06: погашение устаревших находок

**Статус:** реализовано, тесты пройдены; состояние стенда — в [AGENT_HANDOFF.md](AGENT_HANDOFF.md).

Находка в чате остаётся навсегда, а цена живёт часы. Теперь, если товар сняли с продажи или цена поднялась выше
обещанной, бот правит само отправленное сообщение: «Находка уже неактуальна», старая цена зачёркнута, рядом
текущая (или «товара нет в продаже»), кнопки «Открыть товар» и «Искать другие цены». Правка тихая — без
уведомления.

Переменная `TELEGRAM_STALE_MARK`: `off` (по умолчанию) | `on`.

Как устроено:

- При доставке запоминается номер сообщения: колонки `notification_outbox.tg_message_id`, `tg_has_photo`,
  `sent_at` (аддитивные, версия схемы прежняя). Запоминаются находки и одиночные сообщения по наблюдениям;
  сводки из нескольких срабатываний не гасятся.
- `notifier.mark_stale_alerts` вызывается из цикла доставки, но работает не чаще раза в 5 минут и делает не
  больше 5 правок за проход: правка расходует тот же лимит, что и отправка. Пауза Telegram по 429 соблюдается.
- Устаревшие отбирает база (`database.stale_alert_candidates`): отправлено не раньше 72 часов назад, товар снят
  **или** его свежая цена выше обещанной. Решение подтверждает `notifier.stale_verdict`.
- Фото правится через `editMessageCaption`, текст — через `editMessageText`.
- Разобранная находка получает `stale_checked_at` и больше не проверяется. Так же закрываются случаи, когда
  править нечего: сообщение удалено человеком, бот заблокирован, пользователь удалён.

Чего бот намеренно не делает:

- Не гасит находку, если цена товара давно не обновлялась: сбой обхода магазина не делает находку ложной.
- Не гасит подешевевший товар — это всё ещё находка.
- Не возвращает погашенную находку обратно, если цена снова упала: придёт новая находка обычным порядком.
- Не трогает сообщения, отправленные до включения этой возможности, — у них нет сохранённого номера.
- Не трогает наблюдения, чей товар есть только в новой модели предложений (`offers`), а не в `products`.

Не проверено: срок, в течение которого бот может править своё сообщение в личном чате. Документация называет
48 часов только для чужих бизнес-сообщений; для собственных сообщений бота срок не указан.

## 2е. TG-07: карточка `/watches` виджетом

**Статус:** реализовано локально, тесты пройдены (`tests/notifications/test_watches_widget.py`).

Вместо длинной портянки отдельных inline-кнопок «Отключить» на каждое наблюдение бот отправляет одну интерактивную
карточку-виджет (`sendWidget`). В карточке выводятся до 8 активных наблюдений пользователя с иконкой типа (поиск,
товар, категория), условием снижения цены и компактной кнопкой «🔕» прямо в строке.

### Включение

Переменная окружения `TELEGRAM_WATCHES_WIDGET`: `off` (по умолчанию) | `admins` (только `ADMIN_TELEGRAM_IDS`) | `all`.
При любом отказе (`sendWidget` отклонён, список пуст или виджет выключен) бот отправляет прежнее текстовое сообщение.

### Как устроено

- `telegram_widgets.py`: `build_watches_widget`, `build_watches_caption`, `build_watches_chat_data`, `pick_watches`.
- `telegram_bot.py`: `_send_watches_widget`, `handle_watches_command`, обработка `widget_query` с префиксом `d<watch_id>`
  (удаление/отключение наблюдения) и `r` (обновление состояния активных наблюдений).
- При нажатии «🔕»: виджет отправляет запрос боту `d<id>`, бот вызывает `delete_watch(user_id, watch_id)` и тихо
  обновляет `chat_data` карточки (`editMessageWidgetData`). В карточке отключённое наблюдение приглушается с отметкой
  «отключено», активный счётчик уменьшается, а в чат **не сыплются новые служебные сообщения**.
- Кнопка «↻ Обновить»: перечитывает активные наблюдения пользователя и обновляет `chat_data` (с защитой cooldown 30 с).

## 2ж. TG-09: глубокие ссылки с сайта (`t.me/<bot>?start=...`)

**Статус:** реализовано, тесты пройдены (`tests/notifications/test_deep_links.py`).

Позволяет посетителю сайта (включая неавторизованных гостей) подписаться на снижение цены товара или поисковый запрос
в один клик через Telegram-бота по ссылке вида `https://t.me/<bot_username>?start=<payload>`.

### Поддерживаемые действия и формат payload:
1. `wp_<b64url>` — наблюдение за товаром (`kind='product'`). Бот находит товар в базе, автоматически подписывает пользователя
   на любое снижение цены и присылает карточку с текущей лучшей ценой, магазином и кнопкой отмены «🔕».
2. `ws_<b64url>` — наблюдение за поисковым запросом (`kind='search'`). Бот подписывает пользователя на появление новых предложений
   или снижение цен по запросу.
3. `s_<b64url>` — быстрый запуск поиска по запросу в боте (с показом виджета цен).
4. `t_<token>` — токен из таблицы `bot_deep_links` для длинных запросов или сложных полезных нагрузок, превышающих лимит Telegram
   в 64 символа.

### Интеграция:
- `telegram_bot.py`: `encode_deep_link_param`, `decode_deep_link_param`, обработка payload в `handle_start_command` с автоматической
  регистрацией нового пользователя (`upsert_user`) при переходе.
- `database.py`: аддитивная таблица `bot_deep_links (token, action, payload_json, created_at, expires_at)`.
- `web/server.py`: эндпоинт `GET /api/telegram/deep-link?action=...&target=...` возвращает готовую ссылку для фронтенда.
- Шаблоны: в модальном окне наблюдения `search_first.html` добавлена кнопка «✈️ Следить в Telegram-боте (без входа на сайт)»;
  в `index.html` для неавторизованных гостей кнопка «Следить за ценой» переключается на «Следить в Telegram».

## 2з. TG-08: стили кнопок и быстрое копирование ссылки (`copy_text`, `style`)

**Статус:** реализовано, тесты пройдены (`tests/notifications/test_button_styles.py`).

Улучшает эргономику взаимодействия с ботом в чате без спама и лишних переходов:
1. **Быстрое копирование ссылки `copy_text` (Bot API 7.11):**
   - Нативное копирование ссылки на товар или находку в буфер обмена устройства пользователя в один тап (без открытия браузера и всплывающих окон подтверждения).
   - Поддерживается в карточках аномалий цен (`send_telegram_alert`), сообщениях по наблюдениям (`send_watch_message`), ответах поиска `/search` и при подписке на товар через deep link.
   - Выключатель: `TELEGRAM_COPY_BUTTON=on|off` (по умолчанию `on`). Длина текста автоматически укладывается в предел Telegram 256 символов.
2. **Цветовая дифференциация действий `style` (Bot API 9.4):**
   - `primary` (синий акцент): главное целевое действие пользователя — открытие предложения в магазине (`⚡️ Открыть товар`).
   - `danger` (красный акцент): деструктивные или отменяющие действия — отписка/удаление наблюдения (`🔕 Не следить`, `🔕 Отключить: ...`).
   - `success` (зелёный акцент): подтверждение операций.
   - Выключатель: `TELEGRAM_BUTTON_STYLES=on|off` (по умолчанию `on`). Старые клиенты Telegram, не поддерживающие стили, прозрачно отображают стандартные серые кнопки без ошибок API.

## 2и. TG-03 / TG-13: форматированные ответы Rich Message, таблицы цен, сворачиваемые блоки и нативное локальное время (`sendRichMessage`, `expandable`, `<tg-time>`)

**Статус:** реализовано, тесты пройдены (`tests/notifications/test_rich_messages.py`).

1. **Структурированные Rich Messages (`sendRichMessage`, Bot API 10.1+):**
   - Отправка форматированных документов в Markdown до 32 768 символов (вместо стандартного лимита 4096).
   - Нативные Markdown-таблицы сравнения цен по магазинам (`| Магазин | Цена | Товар |`) при текстовом поиске `/search`.
   - Ответы AI-консультанта отправляются в Rich Message с сохранением структуры модели (таблицы, списки, выделения) без потерь при переводе в HTML. При любом отказе выполняется автоматический fallback на `sendMessage` с экранированным HTML.
   - Выключатель: `TELEGRAM_RICH_MESSAGES=on|off` (по умолчанию `on`).
2. **Сворачиваемые блоки цитат (`<blockquote expandable>`, Bot API 7.8+):**
   - Длинные обоснования скидок и цитаты автоматически упаковываются в интерактивный блок, который пользователь может развернуть в один тап.
3. **Нативное локальное время (`<tg-time unix="..." format="...">`, Bot API 9.5, TG-13):**
   - В карточках находок и наблюдениях точное время фиксации цены отображается в формате относительного времени (`format="r"` — «только что», «10 минут назад»), а в `/status` — в формате дня недели и времени (`format="wDT"`).
   - Telegram сам пересчитывает время в локальный часовой пояс и язык пользователя без запроса геопозиции и настроек.
   - Выключатель: `TELEGRAM_NATIVE_TIME=on|off` (по умолчанию `on`).

### Не нужно сейчас

| Возможность | Почему |
|---|---|
| Временные (ephemeral) сообщения, гостевой режим, сообщества, запросы на вступление | Про группы; бот работает только в личных чатах |
| Звёзды, подписки, платные медиа, подарки | Монетизации в плане нет; если появится — цифровые услуги продаются только за звёзды (`XTR`) |
| Платные рассылки (`allow_paid_broadcast`) | Нужны 100 000 активных пользователей в месяц и 100 000 звёзд на балансе |
| TON-кошелёк в виджетах | Платежей в боте нет |
| Бизнес-аккаунты, истории, предложенные посты, управляемые боты, чек-листы | Другой класс ботов; чек-листы описаны только для бизнес-аккаунтов |
| Webhook вместо long polling | Polling работает и не требует открытого порта; webhook имеет смысл при росте нагрузки |
| Реакции как обратная связь на находки | Обновление `message_reaction` требует явного `allowed_updates` и прав администратора чата; для личных чатов не подтверждено |

### Ограничения, о которых стоит помнить

- Рассылка: около 30 сообщений в секунду всего, не чаще одного в секунду в один чат; выше — 429.
- BotFather следит за долей отвеченных личных сообщений и нажатий: на каждое нажатие нужен ответ
  (`answerCallbackQuery`, `answerWidgetQuery`).
- Обновления хранятся на серверах Telegram не дольше 24 часов.
- Собственные эмодзи в сообщениях и на кнопках работают, только если у владельца бота есть Premium.
