## 🔄 1. ЧТО ДЕЛАЕТСЯ СЕЙЧАС (Текущий статус)
* **Статус системы**: Продакшн запущен на [https://shop.molthun.ru](https://shop.molthun.ru) (Synology DSM Reverse Proxy + Docker).
* **Локальная версия**: Активна на `http://localhost:8080` и `http://192.168.28.11:8080`.
* **Текущая версия**: **v2.9.2** — на проде с 2026-09-17 21:50, образы версий v2.6.2 … v2.9.2 собраны в GHCR. Геолокация на проде проверена владельцем.
* **Процесс деплоя**: push в `main` → GitHub Actions (тесты → сборка образа `ghcr.io/molthun/kz-price-hunter`) → Watchtower на Synology проверяет образ каждые 5 минут → `shop.molthun.ru`.
* **Объем каталога**: **20 676+ проверенных товаров** по 11 крупнейшим розничным сетям Казахстана.
* **Обнаружено скидок & аномалий**: **143 подтвержденных супер-скидки / арбитража** со 100% официальными логотипами.
* **Фоновый мониторинг**: Автообновление базы по порогу из настроек (по умолчанию 3 часа, диапазон 5 минут – 30 дней).
* **Последнее изменение**: Список магазинов больше не перекрывается карточками; Live-поиск всегда выключен по умолчанию.

### 🛠 В работе
* Ведение этого журнала: каждое изменение фиксируется здесь (раздел 1 — текущее, 2 — сделанное, 3 — план).
* CI: тег `latest` публикуется только из ветки `main` (`flavor: latest=false` + условие на `refs/heads/main`). Ранее `docker/metadata-action` автоматически добавлял `latest` к каждой сборке semver-тега, из-за чего ручная пересборка тегов откатила прод на v2.8.0.
* Нюанс GitHub: при пуше более 3 тегов за раз сборки по тегам не запускаются — пушить теги по одному/по три или запускать сборку тега вручную.

### 🏷 Правила версионирования
* [SemVer](https://semver.org/lang/ru/): **PATCH** — исправления, **MINOR** — новые функции, **MAJOR** — несовместимые изменения (схема БД без миграции, API).
* Каждый релиз: `version.py` → `CHANGELOG.md` → этот журнал → коммит `type(scope): описание (vX.Y.Z)` → git-тег `vX.Y.Z`.
* Тег `vX.Y.Z` при пуше собирает Docker-образ с тегом версии (`ghcr.io/molthun/kz-price-hunter:X.Y.Z`) — по нему можно откатить прод. Изменения только документации версию не повышают.

### ⚠️ Известные проблемы (аудит кода 2026-09-17)
* **Веб-панель без авторизации** при публичном доступе: `GET /api/config` отдает токен Telegram, `POST /api/config` позволяет менять настройки, сканирование может запустить кто угодно.
* **История git раздута** старыми версиями `prices.db` (18 МБ за коммит) — файл убран из отслеживания в v2.6.2, но остался в истории.
* **`main.py` (CLI) расходится с веб-сканером**: нет Kaspi, счетчики магазинов «1/9», «10 магазинов» не совпадают с 11 сетями; нет фильтра уровня Telegram-уведомлений.

### [2.5.2] — 2026-09-17
- 🎯 **Устранение коллизии артикулов Технодома (`technodom.py`)**:
  - **Причина**: На страницах Технодома ссылки в рекомендательных блоках содержали параметры вида `?recommended_by=dynamic&recommended_code=be191488eb8380d88c40f11d3564e9ff`. Регулярное выражение `r"-(\d+)$"` падало на query string, а фолбэк `rel_link[-15:]` брал хвост хэша `c40f11d3564e9ff`, общий для множества разных товаров. Из-за этого товар за 919 990 ₸ перезаписывался планшетом за 169 890 ₸, создавая фантомную скидку -81.3% и битую ссылку.
  - **Решение**: Реализована полная канонизация URL (отсечение query параметров и хэшей) перед извлечением ID и сохранением в БД.
  - **Ускорение парсинга в 10 раз**: Извлечение всех карточек страницы переведено на внутрибраузерный JavaScript (`page.evaluate()`) — исключены рассинхронизации DOM и сотни асинхронных RPC-вызовов Playwright.
- 🛡 **Защита межмагазинного арбитража (`MARKET_ARBITRAGE`)**:
  - В `database.py` добавлены ценовые коридоры (`0.35 * current_price <= comp_price <= 2.5 * current_price`) и алгоритмическая проверка схожести названий моделей (`difflib.SequenceMatcher >= 0.38`). Исключены ложные сравнения кабелей и БП с готовыми серверами/ПК.
- 🧹 **Очистка базы данных**:
  - Удалены 6 фантомных записей `td_c40f11d3564e9ff` и 39 некорректных алертов с аномальным расхождением > 85%.
